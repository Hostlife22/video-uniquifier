# 变换参考

此页面记录用于受控处理自有或许可媒体的内置转换注册表。顺序指同一媒体类型转换之间的顺序；视频和音频链独立构建。“质量”描述可能的生成损失，而不是第三方匹配系统是否会接受文件。

<a id="recommended-order"></a>

## 推荐顺序

视频: `tonemap_sdr`（转换 HDR 时）→ 画布/几何 → 颜色 → 混合或字幕合成 → 噪声/锐化 → 时域操作。音频: 音高/速度 → 均衡及其他效果 → 重采样 → 最后 `loudnorm`。预检会拒绝可能产生模糊色彩模式、无效响度结果、音视频不同步或不支持的流/容器映射的组合。

<a id="video-transforms"></a>

## 视频变换

|变换|目的和顺序|质量 / 大小|速度| HDR |VFR 和兼容性|
|---|---|---|---|---|---|
| `video.tonemap_sdr` |PQ/HLG → BT.709；必须是第一个视频操作|可见高光/色域重映射；通常输出为较小的 8 位|慢|仅限 HDR 输入；与 `keep_hdr=true` 不兼容|VFR 安全；使原始源 VMAF 参考无效|
| `video.fit_aspect` |通过裁剪、模糊填充或黑色填充适配交付画布；在微裁剪之前。源细节放大默认禁用；固定大小配置文件可通过 `allow_upscale=true` 选择|裁剪会丢失边缘；模糊填充会提高比特率；黑色填充压缩效果好；显式放大不能恢复细节|中等–慢|HDR 几何路径支持裁剪/黑色填充；模糊填充需要先进行 SDR 色调映射|时间戳中性；与 `crop_resize` 结合会增加第二次重采样|
| `video.crop_resize` |小裁剪后再缩放回画布|轻微细节丢失；通常会增加边缘复杂度|中等|支持；颜色转换在线性光下单独封装|VFR 安全；与原始源目标 VMAF 反馈不兼容|
| `video.rotate` |小旋转并填充边界|插值会软化细节，并可能显现角落|中等|支持；HDR 填充使用合法的近黑色|VFR 安全；与原始源目标 VMAF 反馈不兼容|
| `video.mirror` |水平翻转|在编码前像素值无损|快速|支持|VFR 安全；对文本、标志和方向性语义上破坏|
| `video.color_eq` |亮度/对比度/伽马/饱和度调整|在强设置下可能出现截断或条带；比特率影响小|快速|保留 HDR 时使用 Float-RGB 线性光封装|VFR 安全；与噪点保守组合|
| `video.blend_b` |复合许可的 B-roll/视频图层|重影和额外运动会增加比特率|慢；解码第二输入|在保留 HDR 模式下警告：混合是在传输域而非线性光域|VFR输入由FFmpeg归一化，但不同的节奏/持续时间需要质量检查|
| `video.subtitles` |烧录现有的SRT/ASS系列字幕文件|永久光栅化；字形周围比特率略有增加|中等|在色调映射后应用以进行SDR交付；HDR样式需要视觉质量检查|VFR安全；源字幕流保持为独立容器问题|
| `video.noise` |添加类似胶片颗粒的亮度/色度噪声|直接的质量/大小成本；放大后续编码损失|慢|保留 HDR 时使用 Float-RGB 线性光封装|VFR安全；噪声+锐化会加剧振铃和比特率|
| `video.subpixel_sharpen` |轻微的反锐化遮罩|可能会在边缘产生振铃；通常增加比特率|中等|支持，但需检查HDR高光|VFR安全；未经过度测量的质量检查，避免与添加的噪声叠加|
| `video.temporal_jitter` |实验性基于时间戳的黑屏/掉帧效果|破坏性闪烁/抖动；比特率变化|中等|技术上支持，但视觉上不适合HDR|时间戳网格适用于VFR；使原始源VMAF无效，并从以质量为先的配置文件中排除|
| `video.speed` |使用`setpts`更改播放速率|运动节奏变化；文件大小随时长变化|快速视频；额外音频需要AAC编码|支持|需要匹配`audio.pitch_tempo.tempo`；额外音频只改变速度，SRT提示时间和章节边界一起缩放。ASS/位图/定时数据的重定时仍不支持|

<a id="audio-transforms"></a>

## 音频变换

|变换|目的和顺序|质量 / 响度|速度|通道/布局兼容性|
|---|---|---|---|---|
| `audio.pitch_tempo` |音高和/或速度变化；链路早期处理|重采样可能会影响瞬态颜色；Rubber Band质量更高但速度较慢|中等–慢|任何由 FFmpeg 支持的主布局；节奏必须等于 `video.speed.rate`|
| `audio.eq` |参数化频谱塑形|强增益在归一化前可能会削波|快速|布局中性；放在 loudnorm 之前|
| `audio.haas_stereo` |通过延迟一个声道来扩宽立体声|可听到的相位/单声道兼容风险|快速|仅限立体声；预检会拒绝单声道和环绕声|
| `audio.compand` |压缩动态范围|减少动态并改变峰值|快速|布局中性；生产使用前测量自然语音/音乐|
| `audio.spectral_smear` |细微的合唱/移相器调制|在持续音上较强设置时可听见|中等|布局中性；不要盲目叠加效果|
| `audio.reverb` |添加房间/板式回声|可听见并可能降低可懂度|快速–中等|布局中性；放在 loudnorm 之前|
| `audio.noise_overlay` |在程序音频下混合生成的噪声|提高噪声底和 真峰值|中等|布局中性；放在 loudnorm 之前并验证语音/音乐|
| `audio.resample` |中间采样率往返|少量谱/瞬态损失|快速–中等|最终管线输出为 48 kHz AAC；放在 loudnorm 之前|
| `audio.loudnorm` |两遍处理 EBU R128 归一化|目标响度/真峰值；报告动态回退|慢：完整测量过程|音频转换中仅执行一次且为最终执行|

<a id="runtime-compatibility-graph"></a>

## 运行时兼容性图

可执行文件清单为 `core/transform_compatibility.py`；专用媒体检查仍在 `core/preflight.py`。下表描述了所请求领域中每一个硬性或质量敏感的边缘。

|领域|边缘 / 上下文|结果|
|---|---|---|
| HDR | `keep_hdr=true` + `video.tonemap_sdr` |失败：输出颜色模式矛盾|
| HDR |tonemap 不是第一个，tonemap 在 SDR 上，或 HDR 既不保持也不进行 tonemap|编码前失败|
| HDR |在没有 10-bit HEVC 能力的情况下保持 HDR|失败；静态元数据仅在 libx265 上完全验证|
| HDR |保持 HDR + `video.blend_b`|警告：混合不是线性光封装|
|音频|`audio.haas_stereo` + 非立体声主轨|失败|
|音频|loudnorm 之后重复 loudnorm 或任何音频操作|失败|
|音频/时间|视频速度与主音频节奏不同|失败：音视频不同步|
|时间|速度 + 额外音频轨道|仅节奏 AAC 处理；保留轨道元数据和精确目标音频采样数|
|时间/容器|速度 + SRT 或章节|标准 SRT 提取/重定时和明确的章节时钟；无包-BSF 依赖|
|时间/容器|速度 + ASS/位图字幕或定时数据|失败：负载感知重定时未获得资格|
|容器|第一章节从零之后开始 → MP4/MOV|失败：这些章节轨道无法可靠保留前导间隔；请选择 MKV|
|质量|目标 VMAF + 几何、覆盖、镜像、时间、字幕或色调映射操作|失败：原始参考未注册|
|容器|图像字幕 → MP4/MOV|失败；请选择 MKV|
|容器|不支持的附件/数据或处理方式 → MP4/MOV|根据数据是否会丢失决定失败或警告|
|插件|两者都启用时规范中任一声明 `incompatible_with`|对每个无序对失败一次|

警告故意不自动更正：更改变换顺序或禁用效果会改变请求的导数。在长时间编码前运行 `video-uniq preflight` 并查看生成的 FFmpeg 图表。
