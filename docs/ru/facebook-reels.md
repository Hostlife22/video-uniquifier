# Подготовка видео для Facebook Reels: экспериментальный исполнитель

Обработка уже смонтированных видео, которые принадлежат вам или разрешены к распространению.
Результат — MP4 для ручной проверки, отчёт качества, таймлайн сцен и предпросмотры.
Реализация P0/P1 не требует ИИ, моделей или облачных сервисов и не публикует видео.
Версия 2.2.0 использует адаптер API движка, проверенного на базовой ревизии 2.1.2, коммит
`e9138ddbc798cb23e28b44d9edf7959a712f0add`; лицензия MIT сохраняется.
Проверенные API и результаты испытаний описаны в [журнале разработки](facebook-reels-development.md).

<a id="installation-and-cli"></a>

## Установка и CLI

Нужны Python 3.11+, FFmpeg/FFprobe, libx264, loudnorm и colorspace.
Явное преобразование HDR дополнительно требует zscale/tonemap.
Определение сцен по умолчанию требует `[scene]`, HTTP-сервис — `[web]`.

```sh
sh tools/install_reels.sh
.venv/bin/video-reels validate examples/facebook_reels/reels_business_rules.yaml
.venv/bin/video-reels preflight input.mp4 --rules examples/facebook_reels/reels_business_rules.yaml
.venv/bin/video-reels run input.mp4 \
  --rules examples/facebook_reels/reels_business_rules.yaml \
  --asset-root ./assets --root ./reels-jobs --json-events
```

`run` принимает `--job-id`: буквы, цифры, подчёркивания и дефисы, не более 64 символов.
Существующий ID не перезаписывается. Ctrl+C и SIGTERM через нативный CancelToken
останавливают FFmpeg и процесс определения сцен, затем очищают рабочую папку.
Код выхода при отмене — 130, при ошибке конфигурации или обработки — 2.
Причина ошибки записывается в stderr в формате JSON.

GUI, CLI и API используют общее ядро. Стабильный интерфейс `video-uniq` совместим
с прежней версией. В этом предустановленном сценарии используется проверенный программный
libx264; аппаратные кодировщики пока не включены в его контракт доставки.

<a id="desktop-workspace-video-delivery"></a>

## Приложение: Рабочая область → Подготовка видео

```sh
uv pip install --python .venv/bin/python -e '.[gui,scene]'
.venv/bin/video-uniq-gui --reels
```

Раздел готовит смонтированные разрешённые видео с вертикальной предустановкой Reels 9:16.
Откройте его в рабочей области или через `Ctrl+Shift+R`. Между четырьмя шагами можно переходить напрямую:

1. **Выбор видео:** укажите или перетащите файл, проверьте разрешение, частоту кадров,
   длительность и аудиодорожки, выберите папку экспорта.
2. **Настройки обработки:** разделы подготовки видео, звука и таймлайна, заголовка и логотипа.
   Загрузка бизнес-YAML сохраняет дополнительные поля без отдельных элементов GUI.
   Заголовок и логотип по умолчанию отключены; для включения нужны локальные ресурсы.
3. **Предпросмотр и проверка:** проверьте конфигурацию и создайте образец до десяти секунд
   с начала выбранного интервала. Прослушайте речь, проверьте субтитры и безопасные области.
   Изменение исходника или настроек делает старый образец неактуальным.
   Полный экспорт использует весь выбранный интервал.
4. **Экспорт результата:** следите за прогрессом, проверками, предупреждениями и таймлайном сцен.
   Если экспорт завершён на открытой странице, появляется встроенное сравнение исходника
   и результата: синхронное воспроизведение, общая перемотка, покадровая проверка,
   выбор исходного или обработанного звука и разделитель изображения.
   Обрезка по времени выравнивает соответствующий интервал исходника. Последующие изменения
   формы не заменяют пару файлов уже завершённого экспорта.
   Сравнение можно открыть повторно; отдельный встроенный проигрыватель результата работает,
   даже если исходник перемещён. Табличный отчёт сравнивает разрешение, частоту кадров,
   длительность, битрейт, размер и аудиоизмерения. Отдельная вкладка содержит технические
   проверки и пункты ручной приёмки. Неизмеренные значения явно отмечены, а не заменены нулём
   или успешным статусом. JSON остаётся доступным для программной обработки.
   Завершение в фоне не переключает страницу. Успешный полный экспорт попадает в историю.

Задача выполняется в фоновом потоке; глобальное уведомление возвращает к ней.
Отмена останавливает ядро и дочерние процессы, закрытие окна ждёт безопасного завершения.
Полные экспорты сохраняются в `results/<job-id>/` выбранной папки.
Образцы временные и удаляются при выходе. Провал QA не публикуется как готовое видео.

`[gui]` не включает определение сцен: установите `[scene]` или отключите его в настройках
звука и таймлайна. При отсутствии зависимости интерфейс объясняет, что сделать.
Текущая сборка PyInstaller тоже исключает необязательный стек scene.
Обычная обработка видео разделена на исходник и предпросмотр, настройки обработки,
прогресс и результат; действия с образцами находятся в настройках обработки.

<a id="two-configuration-layers"></a>

## Два уровня конфигурации

| Файл | Назначение | Загрузка |
|---|---|---|
| `src/video_uniquifier/profiles/facebook_reels_base.yaml` | Нативный Profile с полями движка | `video-uniq --profile`; необязательный `--profile` исполнителя |
| `examples/facebook_reels/reels_business_rules.yaml` | Кодирование, оформление, сцены, QA, ресурсы | **Только `video-reels --rules`** |

Проверяются нативный Profile и параметры каждого преобразования; бизнес-правила затем
задают fit_aspect, loudnorm и явный tonemap. Стабильные схемы Profile/Plan/RunOptions не изменены.
Пропущенные поля используют строгие значения по умолчанию. Неизвестные поля, повторные ключи YAML,
алиасы, опасные пути, превышения лимитов, NaN/Infinity и численные строки отклоняются.

```sh
.venv/bin/video-reels schema > /tmp/reels-business.schema.json
```

FFprobe проверяет фактические медиа: допустимое расширение не заменяет проверки содержимого.
Лимиты по умолчанию — 2048 MiB, 7200 секунд, 8 847 360 пикселей и две параллельные CPU-задачи.
Это локальные бюджеты, а не ограничения Facebook. `worker.wall_timeout_sec` ограничивает
подпроцессы сканирования, кодирования и предпросмотра; probe, измерения громкости и QA
сохраняют собственные тайм-ауты движка. Потоки кодирования назначаются автоматически, до восьми на задачу.

<a id="defaults-and-limitations"></a>

## Значения по умолчанию и ограничения

- MP4 с faststart, 1080×1920 или 720×1280, H.264 yuv420p, SAR 1:1, SDR Rec.709,
  CRF 21 и veryfast. Сохраняются типовые CFR 23.976/24/25/29.97/30/50/59.94/60;
  VFR преобразуется в 30 CFR.
- Исходник 9:16 сохраняет полный кадр, для прочих пропорций используется `pad_blur`.
  Центральная обрезка требует одновременно `geometry.nonvertical_source: crop`
  и `allow_center_crop: true`.
- HDR/PQ/HLG по умолчанию отклоняется. Для преобразования явно задайте
  `video.hdr_policy: tonemap_sdr`. Широкий охват без надёжной передаточной функции
  и SDR BT.2020 constant-luminance требуют предварительной проверки или конвертации.
  Обычный SDR без маркировки интерпретируется как Rec.709 с предупреждением;
  для надёжно маркированного SDR выполняется цветовое преобразование.
- Выбирается дорожка по умолчанию, иначе первая; фиксируется абсолютный индекс потока.
  Высота и скорость речи сохраняются. Цели двухпроходной нормализации: -16 LUFS,
  -1.5 dBTP и LRA 11; AAC-LC, 48 kHz, стерео, 128 kbps. Кэш учитывает SHA256 входа,
  дорожку, обрезку, цели, версии движка и FFmpeg. Видео без аудио остаётся без аудио;
  тишина отмечается `silent`, нестабильное измерение короткого звука явно указывается.
  `audio.enabled: false` или `audio.loudnorm.enabled: false` отключает нормализацию,
  сохраняя дорожку и её стандартное кодирование.
- Нативный PySceneDetect пишет `scenes.json`, не переставляя и не удаляя сцены, не добавляя переходов.
  `trim_start_sec/trim_end_sec` синхронно обрезают звук и видео; таймлайн хранит координаты
  исходника и результата. Чёрные кадры и тишина — только диагностика. Сцены VFR требуют
  ручной проверки. Нужен `[scene]` либо `scenes.detect_enabled: false`.
  Обрезка источника с отдельными мягкими субтитрами отклоняется; вшитые субтитры сохраняются.
  Сложная конвертация отдельных субтитров вне области этой версии.
- Заголовок человека и PNG-логотип по умолчанию отключены. Лицензированный шрифт должен
  существовать внутри asset-root. Pillow создаёт прозрачные слои для нативной цепочки
  с **одним кодированием видео**. Хеши файлов служат воспроизводимости, а не оценке качества или оригинальности.
- Пример оформления — `examples/facebook_reels/packaging.json`; нужны указанные шрифты и изображения.
  В CLI используется узел `packaging` бизнес-YAML, в API — multipart-поле `packaging` с JSON.
  Пути относительны asset-root; выход за пределы и символические ссылки наружу отклоняются.
  Текст не попадает в shell или выражения FFmpeg. `title.start_sec/end_sec` относятся
  к **обрезанному результату**. Лишние строки не обрезаются молча. Выход за границы
  или вторжение в защищённую область субтитров — ошибка; пересечение заголовка и логотипа — предупреждение.
  На холсте 720 нужно отдельно настроить пиксельные отступы и шрифт.
- Безопасная область — внутренняя эвристика: по 6% слева/справа, 14% сверху, 30% снизу.
  OCR нет, все вшитые субтитры автоматически не определяются. Отдельный `safe-area.png`
  не меняет обложку или видео. `preview.mp4` по умолчанию копирует первые десять секунд
  с точностью до границ пакетов. Оба предпросмотра отключаются независимо.

<a id="outputs-and-quality-gates"></a>

## Выходные файлы и контроль качества

```text
reels-jobs/
├── uploads/<uuid>.<ext>           # HTTP input retained for retry
├── cache/<measurement-hash>.json # Reusable finite loudness measurements
├── work/<job-id>/                # Unpublished work, unavailable for download
├── results/<job-id>/             # Atomic directory publication after QA
│   ├── output.mp4
│   ├── report.json
│   ├── scenes.json               # When scene detection is enabled
│   ├── preview.mp4               # When short preview is enabled
│   ├── safe-area.png             # When safe-area preview is enabled
│   └── *.log / *-layer.png       # Local reproduction diagnostics
├── failures/<job-id>.json         # Failure/cancellation report, no output link
└── jobs.json                     # Local job-state snapshot
```

Отчёт содержит `preset_id/engine_version/job_id/source/output/warnings/quality_check`,
эффективные правила, производный Profile, хеш плана, SHA256 входа/выхода, версию FFmpeg,
argv, выбранный звук, измерения, сцены/чёрные кадры/тишину, попытки и время.
Изменение входа во время обработки запрещает публикацию. Пути и argv — внутренняя диагностика,
они не используются как публичный бизнес-ответ.

QA проверяет MP4/faststart, кодек, размеры, цвет, SAR, частоту кадров, разницу длительности
≤0.5 секунды, параметры AAC-LC, полное декодирование и разницу A/V-начала/конца ≤100 ms.
Допуск громкости — 1 LU, пика — 0.5 dB; превышение 0 dBTP проверяется всегда.
Без надёжных временных меток синхронизация не считается подтверждённой.
`quality_gate.enabled: false` — диагностический режим: ошибки записываются, но экспорт разрешён;
проверяйте `gates_enforced`.

Совпадение временных меток не доказывает синхронизацию речи и губ. Нужны ручные проверки
звука, субтитров, HDR-конвертации и реального интерфейса телефона. После перекадрирования
нет зарегистрированного соответствия эталонных кадров, поэтому исходные SSIM/VMAF не выдаются
за оценку потерь кодирования. `compare_against_source` сравнивает длительность, звук и геометрию;
визуальная похожесть явно не вычисляется. Нет гарантий признания оригинальности, рекомендаций или охвата Facebook.

## HTTP API

```sh
export VIDEO_REELS_API_TOKEN='replace-with-local-secret'
.venv/bin/video-reels serve --rules examples/facebook_reels/reels_business_rules.yaml \
  --root ./reels-jobs --asset-root ./assets --port 8765
curl -H "Authorization: Bearer $VIDEO_REELS_API_TOKEN" \
  -F 'file=@input.mp4' -F 'preset_id=facebook_reels_drama_v1' \
  http://127.0.0.1:8765/api/video-jobs
```

По умолчанию — loopback и один API-процесс. С настроенным токеном все маршруты,
включая OpenAPI `/docs`, требуют Bearer-аутентификации. Обязателен Content-Length;
неограниченная chunked-загрузка отклоняется. Публичную авторизацию, изоляцию пользователей
и постоянную Redis-очередь обеспечивает NestJS; этот сервис — внутренний локальный исполнитель.

| Метод/путь | Запрос/ответ |
|---|---|
| GET `/api/video-presets` | ID, версия и эффективные бизнес-настройки |
| POST `/api/video-jobs` | multipart `file`, `preset_id`, необязательный `packaging` JSON; 202 и состояние |
| GET `/api/video-jobs/{id}` | `job_id,preset_id,status,progress,error,cancel_requested,output_url,report_url` |
| POST `/api/video-jobs/{id}/cancel` | Запрос отмены; cancelled только после выхода; завершённые состояния не меняются |
| POST `/api/video-jobs/{id}/retry` | Только failed/cancelled; 202 и новый ID; после перезапуска загрузить заново |
| GET `/api/video-jobs/{id}/report` | JSON после завершения/сбоя; во время работы — 409 |
| GET `/api/video-jobs/{id}/files/{filename}` | Успешные output.mp4, preview.mp4, safe-area.png, scenes.json |

Состояния: `queued → probing → processing → qa → success`, с переходами в failed/cancelled.
`progress` — 0..1; кодирование использует FFmpeg RunEvent, значение 1 появляется только после
атомарной публикации. Этапы неизвестной длительности показывают фазу без выдуманного остатка времени.

Ответы: 401 — нет авторизации; 404 — неизвестная задача или недоступный файл; 409 — конфликт
состояния; 413 — лимит размера; 422 — конфигурация, имя или пустой файл; 429 — очередь заполнена.
Медиа-ошибки и preflight возвращаются асинхронно через `status=failed,error={code,message,retryable}`:
`missing_video`, `hdr_requires_tonemap`, `trim_duration`, `subtitle_zone_conflict`,
`quality_failed`, `process_failed`, `cancelled`. По умолчанию максимум 32 незавершённые задачи.

RunAdmission согласует CPU-конкурентность CLI и исполнителей одного пользователя:
бюджет во всём развёртывании должен совпадать. Временные сбои кодирования используют
`max_retries`; ошибки настроек и QA автоматически не повторяются. Отмена завершает подпроцессы.
После перезапуска сохраняются завершённые записи; прерванные задачи отмечаются worker_restarted
без ложного обещания восстановления. Снимок содержит последние 1000 записей.
Входы, результаты и кэш требуют отдельной политики хранения. Нельзя запускать несколько
API-процессов с одним jobs-каталогом; межмашинными очередями и повторами управляет BullMQ.

<a id="nestjs-bullmq-integration"></a>

## Интеграция NestJS / BullMQ

Node 22+ адаптер `examples/facebook_reels/bullmq/worker.mjs` не требует дополнительных npm-зависимостей.
Пример WorkerHost:

```ts
@Processor('reels', { concurrency: 2 })
export class ReelsProcessor extends WorkerHost {
  async process(job: Job) {
    return processReelsJob(job, {
      baseUrl: 'http://127.0.0.1:8765',
      // Record cancellation in Redis/database; do not just delete an active BullMQ job.
      isCancelled: async (job) => this.cancellations.isRequested(job.id),
    });
  }
}
```

Импортируйте `processReelsJob`, передавайте `sourcePath/presetId/packaging` из доверенной очереди.
Используйте Node ESM или включите адаптер в сборку Nest. openAsBlob передаёт файл потоком.
Адаптер обновляет `job.updateProgress`, возвращает URL результата и бросает исключение
для attempts/backoff BullMQ. Отмена, ошибки опроса и тайм-аут пытаются остановить Python-задачу.
Каждая попытка BullMQ создаёт новую задачу Python; прежние отчёты об ошибках сохраняются.
NestJS должен проксировать авторизованные загрузки с приватных URL. Meta SDK, токенов и маршрутов
публикации нет. Пример проверен с имитацией HTTP; Redis, авторизацию и хранение подключайте
в существующем приложении NestJS.

<a id="automated-acceptance"></a>

## Автоматическая приёмка

```sh
uv pip install --python .venv/bin/python 'pytest>=9.0.3,<10' 'pytest-cov~=5.0'
.venv/bin/python -m pytest tests/unit/test_reels*.py tests/integration/test_reels_processing.py \
  --cov=video_uniquifier.core.reels --cov-report=term-missing
node --test examples/facebook_reels/bullmq/worker.test.mjs
.venv/bin/python tools/reels_acceptance.py --root /tmp/reels-acceptance
.venv/bin/pytest tests/unit/test_gui_reels.py -q
# Native desktop screenshots/export use the synthetic clip from the previous step.
.venv/bin/python tools/reels_desktop_acceptance.py \
  --source /tmp/reels-acceptance/source-10s.mp4 --out /tmp/reels-desktop-acceptance
```

Скрипт создаёт вертикальный ролик 10 секунд, горизонтальный 30 секунд с 29.97 fps
и вертикальный 90 секунд с 23.976 fps. Полная обработка в 1080×1920 сохраняет исходники,
результаты, отчёты, безопасные области и `acceptance.json`; крупные видео в Git не добавляются.
`--rules` выбирает другую конфигурацию. Повторный каталог использует готовые успешные результаты:
