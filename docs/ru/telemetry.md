# Локальная телеметрия

`video-uniquifier` записывает **нулевую** телеметрию до тех пор, пока вы явно не согласитесь. Когда она включена, ровно одно сводное событие добавляется в локальный файл JSONL в конце каждого завершённого или неудачного кодирования. Сетевого выхода в v0.9 нет — загрузка агрегированных статистик в общий сборщик обсуждается отдельно в версии v1.0 и потребует отдельного шага согласия.

<a id="what-gets-recorded"></a>

## Что записывается

Для каждого кодирования, при успешном или неудачном исходе, следующие поля записываются в `events.jsonl`:

|Поле|Пример|Примечания|
|------------------|----------------------------------|------------------------------------|
| `kind`           | `run_summary`                    |фиксированный|
| `status`         | `completed` / `failed`           |фиксированный набор|
| `profile_name`   | `cid_aware`                      |из YAML пользователя|
| `profile_codec`  | `h264`                           |из Profile.target_codec|
| `encoder_name`   | `libx264`                        |из EncoderCandidate.name|
| `encoder_vendor` | `x264` / `nvenc` / `videotoolbox`|из EncoderCandidate.vendor|
| `wall_clock_sec` | `423.17`                         |время от начала до конца|
| `workers`        | `4`                              |из RunOptions.workers|
| `os`             | `darwin` / `linux` / `win32`     |sys.platform|
| `os_release`     | `25.5.0`                         |platform.release()|
| `python`         | `3.12`                           |только major.minor|
| `segments_done`  | `27`                             |только успех|
| `output_basename`| `clip__cid_aware.mp4`            |только успех; только **basename**|
| `error_summary`  |`PipelineError: …` (первые 200 символов)|только ошибка|
| `schema_version` | `1`                              |увеличен при любом изменении формы, нарушающем совместимость|
| `event_id`       | UUID4                            |уникальный ключ на событие|
| `ts`             |Эпоха Unix|метка на стороне сервера|

Что **никогда** не записывается: пути к исходным файлам, содержимое исходных файлов, хеши файлов, аудиопальцы, тело профиля YAML, длительности, разрешения, трассировки ошибок за пределами первых 200 символов или что-либо, что могло бы идентифицировать исходный артефакт.

Тот же ограниченный рекурсивный редактор установлен перед структурированными журналами, писателями JSONL для аудита и сериализацией телеметрии. Чувствительные имена ключей (`authorization`, cookies, пароли, секреты, API/доступ/приватные ключи и токены), встроенные учетные данные bearer/basic, распространенные формы токенов GitHub/OpenAI и параметры запроса с токенами заменяются на `<REDACTED>`. Публичные поля аудита редактируют каждый абсолютный путь на `<PATH>/<basename>`; структурированные журналы сохраняют только безопасное базовое имя. Prometheus использует фиксированные словари состояния и меток кодировщика и никогда не хранит пути, токены, run ID, plan ID, job ID или segment ID в виде меток.

<a id="what-does-not-go-into-the-event"></a>

## Что *не* попадает в событие

* Полные пути. В конфигурации по умолчанию есть `redact_paths=True`, который переписывает `$HOME` → `<HOME>` в любом строковом поле, которое сохраняется в схеме. Только базовое имя `output_basename` уже не содержит HOME; правило существует как многоуровневая защита.
* Отслеживание ошибок. Мы фиксируем `type(exc).__name__: str(exc)`, усечённое до 200 символов. Внутренние фреймы и локальные переменные остаются вне события.

<a id="where-the-events-live"></a>

## Где живут события

| OS      |Путь|
|---------|--------------------------------------------------------------------------------|
|macOS| `~/Library/Application Support/video_uniquifier/telemetry/events.jsonl`           |
|Linux|`$XDG_DATA_HOME/video_uniquifier/telemetry/events.jsonl` (или `~/.local/share/…`)|
|Windows| `%APPDATA%\video_uniquifier\telemetry\events.jsonl`                               |

Файл вращается, когда достигает 1 МиБ (настраивается по
`TelemetryConfig.rotate_at_bytes`); сохраняется ровно одна резервная копия (`events.jsonl.1`).

Маркер согласия — доказательство того, что вы так или иначе ответили на диалог при первом запуске — находится по адресу
`~/.config/video_uniquifier/telemetry-consent`. Его тело — это буквальная строка `enabled` или `disabled`, чтобы сотрудник службы поддержки мог определить состояние без разбора JSON.

## CLI

```bash
video-uniq telemetry status                      # path, event count, consent state
video-uniq telemetry status --json
video-uniq telemetry export ~/share.jsonl        # copy out for sharing
video-uniq telemetry purge --yes                 # wipe events dir
```

Подкоманды `video-uniq telemetry enable` специально нет. Ее включение должно быть явным кликом в интерфейсе или программным способом
`RunOptions(telemetry=TelemetryConfig(enabled=True))`, чтобы скрипт случайно не изменил глобальный флаг.

## GUI

**Настройки → Локальная телеметрия (с согласия)** включает:

* переключатель **Включено**
* переключатель **Скрывать пути** (включено по умолчанию)
* статус (количество событий + путь на диске)
* **Применить телеметрию** — сохраняет конфигурацию и записывает маркер согласия
* **Открыть папку событий** — показывает каталог в файловом проводнике ОС
* **Очистить события** — необратимое удаление с подтверждением

При первом запуске отображается одноразовое диалоговое окно с двумя кнопками (**Включить**/**Оставить выключенным**); по умолчанию *выключено*. Закрытие диалога без выбора фиксирует "выключено", чтобы больше не показывать запрос.

<a id="programmatic-use"></a>

## Программное использование

```python
from video_uniquifier.core.telemetry import TelemetryConfig
from video_uniquifier.core.orchestrator import RunOptions, run_full

opts = RunOptions(
    work_dir=Path("work"),
    output=Path("out.mp4"),
    telemetry=TelemetryConfig(enabled=True),  # off by default
)
run_full(plan, opts)
```

`record(event, config)` также является публичным, если вы хотите отправлять пользовательские события в тот же файл через собственный пайплайн. Ошибки отслеживаются и логируются через `logging` — телеметрия никогда не изменяет результаты выполнения.
