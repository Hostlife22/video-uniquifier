# Нагрузочное тестирование

Эта процедура квалифицирует существующий сегмент/контрольный пункт/аудио/конкатенированную цепочку; она не вводит вторую цепочку.

<a id="scope-and-evidence-levels"></a>

## Объем и уровни доказательств

Используйте только медиа, которыми вы владеете или на обработку которых у вас есть лицензия. Запустите каждую заявленную комбинацию производства отдельно: контейнер, режим SDR/HDR, кодировщик, конфигурация каналов и хост.

- `VERIFIED`: сохраненные команда, манифест, журналы и JSON для QA/бенчмаркинга существуют именно для этой комбинации.
- `LIMITED`: синтетическая проверка пройдена, но естественный лицензированный корпус не прошел.
- `NOT VERIFIED`: сохраненного запуска не существует. Не делайте вывод о поддержке на основе обнаружения кодировщика.

Базовая конфигурация Intel Mac от 2026-09-03 сохранена в `BENCHMARKS.md`: синтетические запуски 1/2/3 ч SDR libx264 сохранили все `7,200/14,400/21,600` кадры. Одночасовой прерванный запуск повторно использовал первые два сегмента без изменения их SHA-256 или времени изменения файла (mtime). Естественные длинные записи, NFS, NVENC/QSV/AMF и восстановление аппаратного HDR остаются `NOT VERIFIED`.

<a id="prerequisites"></a>

## Предварительные требования

- Среда Python из `make dev` и `.venv/bin/video-uniq`.
- `ffmpeg` и `ffprobe` на `PATH`; libvmaf требуется только для утверждения о хаотическом эквиваленте.
- Фиксированная контрольная сумма исходного файла и достаточно свободного места. Начните с `--dry-run`; не полагайтесь на фиксированную оценку `3× source` для промежуточных файлов с высоким битрейтом.
- Выделенный рабочий каталог и путь вывода для каждого случая. Никогда не делитесь рабочим каталогом между текущими заданиями.

Запись перед каждым запуском:

```bash
shasum -a 256 "$SOURCE"
ffmpeg -version | head -n 1
.venv/bin/video-uniq run "$SOURCE" \
  --profile src/video_uniquifier/profiles/medium.yaml \
  --out "$OUTPUT" --encoder libx264 --work-dir "$WORK" --dry-run
```

<a id="baseline-and-parallel-qualification"></a>

## Базовая и параллельная квалификация

```bash
# Sequential baseline. Keep artifacts so resume identity can be inspected.
.venv/bin/video-uniq run "$SOURCE" \
  --profile src/video_uniquifier/profiles/medium.yaml \
  --out "$CASE_DIR/sequential.mp4" \
  --encoder libx264 --workers 1 --segment-sec 600 \
  --keep-segments --work-dir "$CASE_DIR/sequential.work"

# Parallel run of the same declared combination.
.venv/bin/video-uniq run "$SOURCE" \
  --profile src/video_uniquifier/profiles/medium.yaml \
  --out "$CASE_DIR/parallel.mp4" \
  --encoder libx264 --workers 4 --segment-sec 600 \
  --keep-segments --work-dir "$CASE_DIR/parallel.work"
```

Если охрана водяного знака срабатывает для авторизованного контента, сначала проверьте результат, а затем добавьте `--accept-watermark-risk` в качестве явного подтверждения оператора.

<a id="crash-and-resume"></a>

## Сбой и возобновление

Тест хаоса репозитория запускает весь CLI в отдельной группе процессов, отправляет SIGKILL группе в детерминированные псевдослучайные моменты, возобновляет ту же рабочую директорию и сравнивает результат с чистой базой:

```bash
VIDEO_UNIQ_CHAOS_ROUNDS=3 \
  .venv/bin/pytest tests/chaos/test_random_sigkill.py -q
```

Для длительного ручного случая зафиксируйте `state.json` и манифест завершённых сегментов со значениями SHA-256/mtime непосредственно перед прерыванием. Завершите всю группу процессов CLI/FFmpeg, а не только родительский процесс Python. Возобновите с точно той же командой, путем вывода и рабочей директорией. Не передавайте `--new-variant` во время восстановления.

После возобновления работы каждый сегмент, который был надежно `done` и по-прежнему соответствует записанному SHA-256, должен сохранить свой SHA-256 и mtime. Сегмент `in_progress`, отсутствующий, нулевой или с несоответствующей контрольной суммой, должен быть обработан повторно.

<a id="deterministic-fault-injection-gates"></a>

## Детерминированные врата инъекции ошибок

Запустите до релиз-кандидата:

```bash
.venv/bin/pytest \
  tests/unit/test_orchestrator_checkpoint_lifecycle.py \
  tests/unit/test_checkpoint.py \
  tests/unit/test_main_audio_atomic.py \
  tests/unit/test_concat_segments_workdir.py \
  tests/integration/test_resume_truncated.py \
  tests/integration/test_resume_partial_cleanup.py -q
```

Эти тесты охватывают отклоненное совместное владение, сбой инициализации контрольной точки, поведение контрольной точки `fsync`/заполненный диск, частичную очистку аудио, сбой конкатенации, сбой финальной замены, поврежденные сегменты и частичную очистку. Они утверждают, что существующий опубликованный артефакт выходных данных/состояния/аудио не перезаписывается при неудачной попытке.

<a id="validation-and-acceptance"></a>

## Проверка и приемка

Запустите зарегистрированную диагностику швов для сохраненных границ контрольной точки:

```bash
.venv/bin/python tools/seam_test.py "$OUTPUT" \
  --source "$SOURCE" \
  --work-dir "$WORK" \
  --frames 8 --search-frames 2 --threshold 0.005
```

Инструмент сравнивает декодированные окна источника/выхода, сбрасывает локальные PTS и ищет только в пределах настроенного смещения кадров. Отсутствующая метрика считается ошибкой, а не тихим пропуском. Геометрические/ретайминговые преобразования все еще могут требовать эталона, преобразованного с учётом плана обработки, предложенной в RFC #12; сохраняйте необработанный вывод и не ослабляйте порог, чтобы скрыть незарегистрированную пару.

Для каждого вывода сохраняйте `state.json`, FFmpeg журналы, SHA-256 источника/выхода, QA JSON и результат бенчмарка. Принятие основано на корректности в первую очередь:

|Ворота|Критерий прохождения|
|---|---|
|Декодировать|Основное видео и каждый выбранный аудиопоток декодируются до EOF.|
|Таймлайн|Первый PTS видео, продолжительность, количество потоков/метаданных и дельта A/V соответствуют финальному медиаконракту.|
|Швы|Количество кадров и монотонные временные метки соответствуют ожидаемому ритму; проверяйте исходные данные/вывод вокруг каждой запланированной границы.|
|Возобновить|Допустимые хеши завершенных сегментов и времена модификации не изменены; поврежденные/неполные артефакты перерабатываются.|
|Публикация|Неудачная замена финального аудио/конкатенации оставляет предыдущий действительный артефакт нетронутым и без файла `.part`.|
|Качество|VMAF/SSIM/PSNR интерпретируются только тогда, когда исходные данные/вывод пространственно и временно зарегистрированы; в противном случае отмечаются как неприменимые.|
|Ресурсы|Пик RSS дерева процессов, максимальный уровень использования временного диска, реальное время выполнения и время кодирования сохраняются.|

Битово-идентичные конечные файлы не являются универсальным правилом принятия: планирование потоков кодировщика и метаданные контейнера могут изменять байты. Для фиксированного детерминированного случая требуется точное повторное использование уже завершённых сегментов и проверка конечного медиа-контракта вместе с зарегистрированными показателями качества.

<a id="remaining-mandatory-matrix"></a>

## Оставшаяся обязательная матрица

- Собственный/лицензированный естественный контент длительностью 1 ч, 2 ч и более 3 ч.
- Стерео, 5.1 и несколько аудиодорожек; MP4, MKV и MOV.
- SDR, HDR10 и HLG для каждого заявленного кодировщика.
- APFS/локальный диск плюс любая фактически развернутая сетевая файловая система.
- Тесты на отключение питания/перезагрузку и низкое пространство на временном томе.

Никогда не имитируйте полный диск на основном томе разработчика. Используйте временный образ, контейнер или выделенного CI-исполнителя и сохраняйте доказательства восстановления.
