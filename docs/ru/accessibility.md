# Доступность

`video-uniquifier` нацелено на соответствие **WCAG 2.1 уровня AA** для настольного графического интерфейса (`video-uniq-gui`) и для необязательного веб-интерфейса (`video-uniq-web`). Эта страница представляет собой заявление о соответствии, чек-лист ручного тестирования и обоснование для нескольких критериев уровня AA, где мы применяем документированную адаптацию для настольного варианта вместо буквальной веб-формулировки.

CLI (`video-uniq …`) наследует доступность эмулятора терминала пользователя и программы чтения с экрана; оно не входит в область охвата WCAG и здесь не проверяется.

<a id="desktop-adaptations"></a>

## Адаптации для настольных систем

Некоторые критерии уровня AA написаны для веб-страниц и не переводятся буквально в настольное приложение Qt. Мы следуем руководству рабочей группы [WCAG2ICT](https://www.w3.org/WAI/standards-guidelines/wcag/wcag2ict/), когда буквальный текст не применим.

| SC          |Веб-формулировка|Интерпретация для настольного приложения, которую мы применяем|
|-------------|----------------------------------------|--------------------------------------------------------------------------------------------|
| 2.5.5 AAA   |Цели ≥ 44×44 CSS-пx|≥ 20×20 device-px для `QPushButton` (соответствует стандартному размеру Qt per-platform sizeHint: Linux ≈ 22, Windows ≈ 20, macOS ≈ 22-24). Пользователи в сенсорном режиме получают увеличитель на уровне ОС.|
| 1.4.4       |Изменение размера текста до 200 % без прокрутки|Поддерживается через `QApplication.font()` + масштаб DPI ОС; `QT_FONT_DPI` и `QT_SCALE_FACTOR` учитываются.|
| 3.2.5       |Смена контекста только по запросу|Переключение темы — по желанию через экран настроек; автопереключение при фокусе отсутствует.|

<a id="keyboard-reference"></a>

## Справка по клавиатуре

Каждый экран полностью управляется с клавиатуры. Полный список комбинаций клавиш:

|Аккорд|Действие|
|------------------------------|---------------------------------------------|
| `Tab` / `Shift+Tab`          |Переместить фокус вперед / назад.|
| `Ctrl+1` … `Ctrl+9`          |Перейти к элементам боковой панели 1–9.|
| `Ctrl+0`                     |Перейти к Настройкам (элемент боковой панели 10).|
| `Enter` / `Space`            |Активировать выбранную кнопку или флажок.|
| `Esc`                        |Отменить активный запуск (RunScreen, Batch).|
| `Ctrl+R`                     |Запустить активную задачу (RunScreen).|
| `F1`                         |Открыть встроенную справку (где доступно).|

Боковая панель — это основная область работы с клавиатурой — если вы потеряете фокус, нажмите
`Ctrl+1`, чтобы попасть на Run, и используйте Tab оттуда.

<a id="screen-reader-manual-test-guide"></a>

## Руководство по ручному тестированию с экранным чтецом

CI проверяет статический контракт; сам опыт лучше всего проверять с помощью реального экранного чтеца. Мы тестируем на:

- **macOS**: VoiceOver (`Cmd+F5`).
- **Windows**: NVDA (бесплатно, [nvaccess.org](https://www.nvaccess.org/)).
- **Linux**: Orca + AT-SPI bridge (gnome-shell, KDE, XFCE — все работают).

<a id="smoke-test-10-minutes"></a>

### Тест на работоспособность (10 минут)

1. Запустите `video-uniq-gui`. Экранный диктор должен объявить
   **"video-uniquifier окно, Основной список навигации, Выполнить"**.
2. Нажимайте `Ctrl+1` через `Ctrl+0`. Каждый шаг должен объявлять заголовок нового экрана (например, *"Экран Выполнить"*, *"Экран Настройки"*).
3. На экране Выполнить нажимайте `Tab` повторно. Каждый сфокусированный элемент управления должен объявлять как свою **роль**, так и **доступное имя** (например:
   *"Входной файл, поле редактирования"*, *"Обзор, кнопка"*).
4. Активируйте кнопку Обзор с помощью `Space`. Должен открыться встроенный выбор файла — его доступность обеспечивается ОС, а не нами.
5. Перейдите в Настройки (`Ctrl+0`), переключитесь на выпадающий список темы и измените тему. Читалка должна озвучить новое название темы; фокус не должен теряться на диалоговом окне, которое клавиатура не может закрыть.

Если какой-либо шаг проходит без звука или озвучивает *"кнопка без метки"*, создайте
`a11y` заявку с указанием экрана, имени и версии экранного читалки, а также неработающей комбинации клавиш.

<a id="known-limitations"></a>

## Известные ограничения

- **Диаграммы Web UI**: пакеты Plotly поставляются с собственной ARIA-разметкой; мы добавляем подписи к осям, но пока не предоставляем текстовую альтернативу в табличном виде для данных, доступных только зрячим. (Отслеживается как работа для v1.1.)
- **Индикаторы прогресса CLI**: метки в стиле tqdm обновляются быстрее, чем интервал опроса большинства экранных читалок. Передайте `--no-progress`, чтобы использовать одну итоговую строку в конце выполнения, которая полностью читаемая.
- **Голосовой помощник Mac VoiceOver в Qt 6.7**: известная системная ошибка ([QTBUG-118473](https://bugreports.qt.io/browse/QTBUG-118473)) время от времени не озвучивает роль на `QPushButton`. Название при этом читается правильно; мы перейдем на Qt 6.8 после того, как PyQt6 выпустит для него пакеты.

<a id="reporting-an-a11y-issue"></a>

## Сообщение о проблеме доступности

Задачи на GitHub с меткой **`a11y`** попадают в ту же очередь триажа, что и отчеты о безопасности, с целевым сроком подтверждения 5 рабочих дней. Пожалуйста, включите:

- ОС + версия, программа чтения с экрана + версия, версия приложения (`video-uniq-gui --version`) и установленная версия PyQt6/Qt.
- Точный экран + сочетание клавиш, которые не сработали.
- Ошибка возникает в *озвучивании* (нет озвучивания, неправильный текст, неправильная роль) или в *взаимодействии* (недоступный элемент управления, потеря фокуса, клавиатурная ловушка).

Мы рассматриваем любое регрессивное изменение AA как блокирующее выпуск патч-релиза v1.0.x; улучшения AAA попадают в следующий минорный релиз.
