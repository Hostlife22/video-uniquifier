# Калибровка

`video-uniq calibrate` проверяет интенсивность существующего профиля для обработки принадлежащих или лицензированных медиа. Он сравнивает исходный материал с авторизованным производным с помощью локальной инженерной диагностики. Он не предсказывает YouTube Content ID или любую другую внешнюю систему управления правами.

Команда остается экспериментальной: пороги схожести зависят от корпуса, и короткий репрезентативный образец не может доказать качество всего файла. Всегда запускайте настроенный профиль на полном источнике и проверяйте окончательный отчет QA перед публикацией.

<a id="quick-start"></a>

## Быстрый старт

```bash
video-uniq calibrate /path/to/master.mp4 \
  --base src/video_uniquifier/profiles/medium.yaml \
  --out /path/to/tuned.yaml \
  --target 0.2 \
  --min-quality 88.0 \
  --iterations 7 \
  --clip-sec 60.0 \
  --metric chromaprint

video-uniq run /path/to/master.mp4 \
  --profile /path/to/tuned.yaml \
  --out /path/to/derivative.mp4
```

`chromaprint` использует смешанную максимальную pHash/аудио диагностику и требует `fpcalc` для источников с аудио. Отсутствие необходимых отпечатков приводит к прерыванию, вместо того чтобы сделать визуально допустимым кандидата только по изображению. `sscd` требует необязательных зависимостей `[ml]` и значительно тяжелее.

<a id="calibration-v2-behavior"></a>

## Поведение калибровки v2

1. Общий бюджет `--clip-sec` распределяется по началу, середине и концу длинного источника. Источник, короче бюджета, используется как один полный клип.
2. Три окна копируются потоком и соединяются в одну систему проверки с ключом содержимого. Это избегает траты бюджета на кодирование в три раза больше запрошенного.
3. Каждый кандидат использует `seed_strategy: fixed` и одинаковое начальное значение (seed), поэтому стохастические шаблоны преобразования не перемещают цель между испытаниями.
4. Поиск сначала измеряет фактор `1.0`, нижнюю границу `0.25` и верхнюю границу
   `4.0` (с учетом бюджета итераций). Затем он делит информативные интервалы по логарифмической шкале. Не предполагается, что стек преобразований является монотонным.
5. Каждый кандидат проходит через существующий конвейер `build_plan` и `run_full`. Неудача кодирования/оценки повторяется один раз с тем же фактором, а затем прерывается; она никогда не преобразуется в плохую оценку.
6. Сходство и воспринимаемое качество являются независимыми ограничениями. Кандидат считается допустимым только тогда, когда оба критерия пройдены.
7. Бэкенд качества, использованный в первой успешной попытке, фиксируется для поиска. Если бэкенд меняется между VMAF и SSIM, калибровка прерывается вместо того, чтобы сравнивать несовместимые значения.
8. Полные оцененные попытки кэшируются атомарно по хэшу плана, версии алгоритма и метрике сходства. Повторный запуск прерванного поиска может использовать ранее полученные измерения. Изменённый источник, профиль, кодировщик, начальное значение (seed), версия инструмента или метрика получают другой ключ. Незавершённые артефакты runner/output изолированы по сеансам, чтобы одновременные GUI или CLI поиски не могли испортить друг друга. Пользовательские обратные вызовы программного оценщика сознательно обходят этот кэш.
9. Среди допустимых кандидатов результат отдаёт предпочтение более высокой измеренной качественности, а затем более мягкому фактору. Если ни один кандидат не подходит, возвращается кандидат с наименьшим нормализованным нарушением ограничения и выполняется выход с кодом 2.

Три базовых испытания сделаны намеренно. Калибровка, таким образом, не останавливается только потому, что фактор `1.0` прошёл; дополнительная информация позволяет выявить резкие изменения качества и немонотонное поведение. Многоразовое использование испытаний компенсирует эти затраты при повторных прогоне.

<a id="quality-threshold-semantics"></a>

## Семантика порога качества

`--min-quality` не является универсальной перцептуальной единицей:

|Бэкэнд|Сообщённое значение|Обычная доступность|
|---|---:|---|
| VMAF |родной балл 0..100|FFmpeg создано с `libvmaf`|
| SSIM |средний SSIM × 100|резервный вариант, когда VMAF недоступен|

pHash не является резервной функцией перцептивного качества. CLI и GUI всегда показывают бэкенд рядом со значением. Рассматривайте эксперимент VMAF и эксперимент SSIM как разные калибровки, даже если оба используют числовой порог `88`.

<a id="options"></a>

## Опции

|Флаг|По умолчанию|Инженерное значение|
|---|---:|---|
| `--target` | 0.2 |Диагностика максимального локального сходства источника/производной; не внешняя вероятность|
| `--min-quality` | 88.0 |Минимальный балл для явно отчетного бэкенда VMAF или SSIM|
| `--iterations` | 5 |Общий бюджет испытаний с ограниченным поиском; используйте 7–9 для разнородных длинных источников|
| `--clip-sec` | 60.0 |Общее время, распределенное по началу/середине/концу окон|
| `--metric` |chromaprint|`chromaprint` или `sscd` локальная диагностика|
| `--encoder` |auto|Закрепление, когда в производственном кодировании будет использоваться конкретный энкодер|
| `--work-dir` | `.video_uniq_calib` |Каталог кеша для зондирования, кандидатов, работы и оцененных пробных запусков|

<a id="reading-the-result"></a>

## Чтение результата

`converged` означает, что хотя бы один измеренный кандидат прошел оба ограничения в пределах запрошенных границ коэффициента. Это не означает, что весь фильм был квалифицирован.

`not converged` означает, что ни один выбранный кандидат не прошел оба критерия. Обычные причины — плоская/шумная диагностика сходства, источник с уязвимым качеством, неподходящий базовый профиль или слишком маленький бюджет итераций. Проверьте каждый шаг на стороне сервера и заметки; не компенсируйте это слепым повышением силы преобразования.

Каталог работы можно использовать повторно. Шаг, отмеченный `scored-trial cache hit`, не был перекодирован. Удаляйте только этот каталог калибровочной работы, если вы намеренно хотите выполнить новое измерение при иных одинаковых вводных данных.

<a id="programmatic-api"></a>

## Программный API

```python
from pathlib import Path

from video_uniquifier.core.calibration.loop import CalibrationTarget, calibrate
from video_uniquifier.core.profile_loader import dump_profile, load_profile

base = load_profile(Path("profiles/medium.yaml"))
result = calibrate(
    input_path=Path("/movies/master.mp4"),
    base_profile=base,
    target=CalibrationTarget(
        max_self_match=0.15,
        min_quality=86.0,
        max_iterations=8,
        test_clip_sec=90.0,
        seed=0,
        min_factor=0.25,
        max_factor=4.0,
    ),
    work_dir=Path("/tmp/calib"),
)

print(result.converged, result.factor, result.final_quality_metric)
dump_profile(result.profile, Path("tuned.yaml"))
```

`CalibratedResult.steps` записей каждого оцениваемого фактора, профиля, балла сходства, значения качества/бэкенда, затраченного времени на оценку и заметок о кэше/резервной версии. Пределы проверяются перед любой работой с медиа и должны удовлетворять
`0 < min_factor <= 1 <= max_factor`.

Калибровка только масштабирует параметры с существующим правилом интенсивности. Она не переключает преобразования, не меняет порядок графа фильтров, не выбирает вторую конвейерную обработку и не заменяет полную проверку правильности и качества вывода.

<a id="intensity-rules-and-scoring-domain"></a>

## Правила интенсивности и область оценки

См. [решения по реализации аудита](https://github.com/Hostlife22/video-uniquifier/blob/d6af67ac05eb0689f958f18cca08cfdb6cb7c4db/docs/audit-implementation-decisions.md) для текущих правил параметров, фиксированных эффектов, пределов и миграции кэша. Сырой калибровочный показатель качества сравнивает источник и кандидата; он отличается от зарегистрированного качества кодирования. Сырой HDR не поддерживается. Видеовход можно оценивать с помощью визуальной диагностики; ошибка извлечения аудио для источника с аудио является ошибкой. Схема кэша 3 фиксирует фактические версии исполняемых файлов и официальную идентичность модели SSCD.
