# Справочник GUI

`video-uniq-gui` — это настольный пользовательский интерфейс для video-uniquifier. Он полностью повторяет CLI 1:1 — всё, что вы можете сделать через `video-uniq <cmd>`, вы можете сделать здесь, плюс некоторые дополнительные функции (редактор профилей, история запуска, встроенный просмотрщик QA, мастер валидации).

<a id="install-launch"></a>

## Установка и запуск

```bash
pip install 'video-uniquifier[gui]'
video-uniq-gui
```

`PyQt6-WebEngine` (~150 МБ) обеспечивает работу встроенного просмотрщика QA. Если он отсутствует или запускается в режиме без GUI (например, на CI для тестирования), просмотрщик QA заменяется меткой + кнопкой «Открыть в браузере».

<a id="screen-overview"></a>

## Обзор экрана

Левая боковая панель группирует свои десять экранов на Workspace, Tuning & Quality, Library и Tools. Каждая страница имеет заголовок и объяснение. Dark studio является темой по умолчанию для новой сессии; светлая тема использует ту же систему компонентов. Раскрывающиеся панели плавно появляются; **Settings → Reduce interface motion** отключает эти анимации. Таймкоды используют моноширинный системный шрифт. Содержимое страниц прокручивается в небольших окнах, не смещая основные элементы управления за пределы экрана. Существующие предпочтения остаются в силе. Навигация вызывает хук `on_show()` каждого экрана, поэтому состояние остаётся актуальным. Статус готовности, уведомление о локальной обработке и версия приложения расположены вместе по центру в нижней панели.

**How to use** в заголовке каждой страницы открывает встроенный быстрый старт: три шага, основные термины для этого раздела и практический совет. Нажмите **F1**, чтобы открыть или закрыть руководство текущей страницы, даже когда боковая панель находится в фокусе клавиатуры.
**Скрыть руководство** закрывает его и возвращает фокус на кнопку заголовка. Помощь начинается в свернутом виде, следует выбранному английскому/русскому языку и теме, и сохраняет доступными рабочие элементы управления и фоновые задачи. Для вашего первого видео начните с обработки видео и просмотрите короткий образец перед обработкой полного файла.

<a id="1-process-video-run"></a>

### 1. Обработать видео (Запуск)

Уникализация одного файла.

Рабочее пространство **Process video** размещает исходный и целевой материалы бок о бок в верхней части, большой проигрыватель слева с паузой по умолчанию и прокручиваемый инспектор настроек справа. Полноширинная шкала прогресса/результатов появляется внизу при начале обработки; при новой сессии это пространство используется для предварительного просмотра. Журнал активности находится под результатом. Его свернутый заголовок занимает одну строку; разверните его, чтобы прочитать сообщения, и перетащите разделитель для изменения высоты. Переключитесь между **Original / Processed**, чтобы просмотреть исходный материал или последний завершенный результат. Используйте воспроизведение/паузу, ползунок перемотки (включая стрелки на клавиатуре) и **Sound**. Предварительный просмотр останавливается, когда страница скрыта или начинается обработка. Ошибки встроенных кодеков отображаются рядом с проигрывателем; они не отключают обработку.

Перетаскивайте разделители панели, чтобы изменить размеры панелей. Сфокусируйтесь на разделителе с помощью Tab и используйте клавиши Влево/Вправо или Вверх/Вниз для изменения размера с клавиатуры. Приложение сохраняет размеры при выходе и восстанавливает их при следующем запуске. **Сбросить макет рабочей области** внизу инспектора восстанавливает пропорции по умолчанию. Фиксированная нижняя панель действий остается видимой.

![Рабочее пространство студии с изменяемым размером и синтетическим демонстрационным клипом](../screenshots/run-screen.png)

Рабочий процесс содержит следующие разделы:

1. **Входное видео / Сохранить результат в** — выберите или перетащите локальное видео в верхнюю панель. Наведите курсор на имя файла, чтобы увидеть его полный путь. GUI считывает его кодек, размеры, частоту кадров, длительность и HDR-флаг в фоновом режиме. Источник отображается в большом плеере и предлагает `<source>.processed.mp4` рядом с входным файлом, с суффиксом, если такой файл существует. Ручной выбор места назначения сохраняется при изменении источника. Источник и выход не могут быть одним и тем же путем.
2. **Профиль обработки** — выберите компактную карту Gentle, Medium или Strong. Раскройте **Что меняет этот профиль** для выбранных деталей изображения/аудио рецепта. Новая сессия начинается с `soft`; сохранённый профиль выигрывает.
3. **Попробуйте короткий образец** — **Обработка образца** остаётся внизу инспектора, пока его настройки прокручиваются. Просмотрите образец по умолчанию или раскройте **Выбрать интервал образца**, чтобы изменить его начало и продолжительность.
   **Расширенные и пользовательские профили** ниже содержат полный выбор профиля, выбор кодировщика, рабочую ссылку **Редактировать профиль** и автотюнинг. Выбор пользовательского рецепта автоматически открывает эти элементы управления.
4. **Прогресс и результат** — появляется, когда задача запускается; следите за прогрессом видео/аудио и статусом сегментов. Завершённые запуски отображают **Открыть обработанное видео** и **Открыть отчёт о качестве**. Панель результатов показывает эти действия после завершения обработки. **Измеренные метрики** — отдельный свернутый блок для диагностических значений. Действие с видео сохраняет путь к завершенному файлу, даже если следующая целевая папка изменится.

Фиксированная панель действий объясняет, что отсутствует, и предоставляет **Проверить видео** и
**Начать обработку** (`Ctrl+P` / `Ctrl+R`). Проверки также выполняются в рамках конвейера обработки. Блокирующая ошибка остаётся активной до изменений во входных данных/профиле/кодере; результаты старых настроек отбрасываются. Во время обработки элементы управления входными данными отключены, а кнопки **Приостановить**/**Отменить** становятся доступны.

**Установить начало сэмпла** над основным плеером выбирает текущую позицию воспроизведения источника и отображает элементы управления сэмплом в инспекторе. Чтобы изменить сэмпл, разверните **Выбрать интервал сэмпла**, выберите начало на миниатюре киноплёнки или введите `HH:MM:SS.cc`, выберите длину 10, 15 или 20 секунд, затем нажмите **Обработать сэмпл**. Киноплёнка декодирует пять маленьких кадров в фоновом потоке с возможностью отмены; нажмите или перетащите, чтобы выбрать начало, или используйте стрелки для перемещения на секунду. Выбор сокращается в конце более короткого источника. Без потерь FFV1/PCM-референс обрабатывается через выбранный профиль и обычный процесс/QA-пайплайн. Полная информация о назначении и истории запуска остаётся без изменений.**Сохранить сэмпл…** копирует обработанный MP4 в выбранное место; сохранённые копии остаются доступны после закрытия приложения. Сохранение можно отменить и атомарные и не могут перезаписать исходный источник или временные файлы обзора, включая псевдонимы через символьные ссылки или жесткие ссылки. Несохраненные образцы временные: создание другого образца или закрытие приложения удаляет их. HDR-образцы отключены, потому что этот формат ссылок не может гарантировать сохранение всех HDR-метаданных; обработка полного файла остается доступной.

![Элементы управления образцом в инспекторе студии](../screenshots/sample-screen.png)

Когда образец завершает воспроизведение, **Before / after** открывается автоматически. Полные завершённые прогонки открывают **Compare before / after**. Оба плеера имеют общие кнопки воспроизведения/паузы и шкалу времени; слышен только выбранный саундтрек. Выбирайте бок о бок, оригинал или результат, либо **Draggable divider**. Разделитель накладывает два SDR-кадра на один холст: перетаскивайте его ручку или используйте клавиши Left/Right, Home и End. Слева показывается источник, справа — результат; различия в кадрировании/повороте остаются видимыми. Известные PQ/HLG HDR-кадры используют нативные видео панели вместо растрового разделителя. Выбирайте fit-to-window, 50%, **100%**, 200% или 400% (100% — один декодированный пиксель на физический экранный пиксель). Перетаскивайте увеличенные изображения для прокрутки; разделитель использует одинаковое смещение для обоих изображений, а бок о бок панели синхронизируют долю прокрутки. Кнопки кадра ставят на паузу и используют ближайшие раскодированные временные метки, включая кадры с переменной частотой. **Sync by time** использует общий временной диапазон;
**Синхронизация по длительности** также отображает время и скорость воспроизведения для постоянных изменений темпа. Эти режимы не регистрируют соответствующие сцены после произвольных изменений. Если кодек недоступен в родном плеере, ошибка отображается в окне; существующее действие **Открыть обработанное видео** по-прежнему открывает системный плеер.

![Просмотр до/после на macOS](../screenshots/review-screen.png)

Обработка идентифицирует этапы подготовки, видео, аудио, сохранения и проверки качества. Процент описывает текущий этап или наблюдаемый проход аудио, а не выдуманный процент всей работы. Прошедшее время не учитывает паузы. Оценка оставшегося времени применима к текущему этапу и появляется только после нескольких измерений прогресса; она сбрасывается для новых этапов, проходов по метрикам и повторных попыток, и исчезает, когда прогресс останавливается или не имеет измеримой доли.

Глобальный баннер активности остаётся в верхней части страницы, когда активен запуск, пример, сохранение примера, авто-настройка, пакетная обработка или очередь. Перемещайтесь свободно и используйте **Вернуться к задаче**, чтобы повторно открыть её экран. Когда несколько рабочих процессов активны, выберите задачу в баннере. Неизвестный прогресс отображается индикатором неопределённой длины, а завершённые задачи автоматически убирают баннер.

![Прогресс задачи при просмотре Настроек](../screenshots/activity-screen.png)

**Журнал активности** изначально свернут и открывается автоматически при записи ошибки. Его также можно развернуть с помощью клавиатуры. Автоматический выбор кодировщика остаётся доступным; ручной выбор передаётся в существующий API ядра.

Расширенные метрики используют адаптивные KPI-индикаторы, окрашенные по группе:
- **pHash худший фрагмент** — зелёный < 0.75, жёлтый < 0.85, красный ≥ 0.85
- **Средний VMAF** — зелёный ≥ 85, жёлтый ≥ 75, красный < 75
- **Аудио FP Хэмминг** — зеленый ≥ 18 бит, желтый ≥ 10 бит, красный < 10
- **Макс. сходство** — старые диапазоны отображения: зеленый < 0.2, желтый < 0.4, красный ≥ 0.4

Эти цвета являются локальными диагностическими диапазонами отображения, а не вероятностями, диапазонами качества для человека или предсказанными Content ID результатами. Отсутствующие измерения отображаются как `n/a`.

<a id="2-batch-processing"></a>

### 2. Пакетная обработка

Итератор каталога файлов. Выберите входной каталог + выходной каталог + шаблон glob (по умолчанию `*.mp4`) + профиль + кодировщик. Подходящие файлы отображаются в таблице; нажмите ▶ Запустить пакет, и каждая строка обновляет свой статус (ожидание → выполнение → завершено / ошибка) по мере прогресса рабочего процесса.

Выберите несколько строк с помощью Ctrl/Cmd или Shift и используйте **Обработать выбранное**, чтобы запустить только эти видимые файлы. **Запустить пакет** обрабатывает каждый файл в совпадающем предварительном просмотре, включая строки, скрытые поиском или фильтром статуса. Обе команды захватывают список файлов при запуске; файлы, появившиеся позже в папке, относятся к следующему пакету. Входные данные остаются недоступными во время выполнения, в то время как поиск и выбор списка остаются доступными.

"Продолжить при ошибке" позволяет пакету продолжать выполнение при ошибках отдельных файлов (по умолчанию); снимите галочку, чтобы остановиться при первой ошибке.

![Инструменты пакетного выбора и общая таблица](../screenshots/batch-screen.png)

Таблицы истории, пакетов и очередей используют элементы управления **Поиск** и **Все статусы**. Поиск включает полные пути; элементы очереди охватывают очереди на исполнение, в процессе, завершённые и неудачные, за исключением файлов состояния/ошибок воркера. Нажмите на заголовок, чтобы отсортировать, перетащите его край, чтобы изменить размер, или перетащите заголовок, чтобы изменить порядок столбцов. Размеры столбцов, порядок и настройки сортировки сохраняются при выходе. Обновления сохраняют выбранные идентификаторы файлов.

Флажок в верхнем левом углу таблицы выбирает или снимает выделение со всех видимых строк; тире указывает частичный выбор. Он выбирает строки без изменения эффектов профиля. Используйте **Выбрать видимые строки** для массового выбора и **Копировать пути** для выбранных видимых файлов. Скрытие строки удаляет её из выбора. Каждая строка предлагает кнопки файла и содержащей папки; история также может открыть её QA-отчёт. Щёлкните правой кнопкой мыши по строке для тех же действий с файлом/папкой, копирования выбранных путей или выбора видимых строк. Цвета статуса всегда включают текст; полные пути доступны при наведении курсора. Эти команды выбора не удаляют файлы из очереди или записи истории.

<a id="3-auto-tune-calibrate"></a>

### 3. Автонастройка (Калибровка)

Поиск интенсивности профиля относительно целевого самосопоставления. Выберите источник + базовый профиль + целевое самосопоставление (по умолчанию 0.2) + минимальное качество (по умолчанию
88) + итерации (по умолчанию 5) + общее время зондирования в секундах (по умолчанию 60, распределено на начало/середину/конец). Диаграмма отображает три серии для каждого испытания:
`intensity_factor`, `self_match`, `quality / 100`. После завершения нажмите «Сохранить откалиброванный профиль как…», чтобы записать результат.

Если калибровочный цикл не сошелся («⚠ лучший на данный момент»), сохраненный профиль является кандидатом с наименьшим нарушением, который был доступен, но он не прошел обе проверки. Проверьте указанные показатели VMAF/SSIM и кандидаты перед изменением бюджета клипа, базового профиля или порога.

<a id="4-quality-reports-qa-viewer"></a>

### 4. Отчеты о качестве (QA Viewer)

Два режима:
- **Открыть существующий** — выберите любой `.qa.html` и отобразите его встроенным.
- **Вычислить новый** — выберите пару (вход/выход) и вычислите отчет на месте. Пути для выхода записываются рядом с выходным файлом как
  `<output>.mp4.qa.json` / `.qa.html`.

<a id="5-profiles-profile-editor"></a>

### 5. Профили (Profile Editor)

Редактирование профиля YAML в строке. Выберите профиль из выпадающего списка; таблица трансформаций загружается с тремя колонками:
- ID трансформации (красным, если отсутствует в текущем реестре)
- флажок включения
- параметры в формате JSON (редактируемые)

Селектор верхнего уровня `seed_strategy` ниже. Эффекты и живой предварительный просмотр YAML расположены на отдельных вкладках, что позволяет редактору оставаться читаемым в узком окне. "Сохранить" перезаписывает с резервной копией `.yaml.bak`; "Сохранить как…" запрашивает новый путь.

Некорректный JSON в любой ячейке параметров предотвращает сохранение и отображает QMessageBox с номером строки.

<a id="6-history"></a>

### 6. История

Последние 100 запусков (ограничено, сохраняется в
`~/.config/video_uniquifier/history.json`). Кнопки "Открыть вывод" + "QA" для каждой строки. Поле фильтра совпадает по исходному коду / профилю / кодировщику / статусу. "Очистить все" удаляет файл.

<a id="7-corpus"></a>

### 7. Корпус

CRUD над локальным индексом отпечатков. Добавить файл → CorpusWorker индексирует его в фоновом режиме (несколько секунд для длинного видео). Удалить выбранные строки по ID.

<a id="8-queue"></a>

### 8. Очередь

Две подвкладки:
- **Управление очередью** — выберите корень очереди (должен находиться на общем файловом хранилище с поддержкой атомарного переименования), «Инициализировать очередь здесь» создаёт pending/ in_progress/ done/ failed/, «Добавить файлы…» делает жёсткие ссылки файлов в pending/, баннер с живой статистикой обновляется каждые 2 с.
- **Управление воркером** — запуск однопроцессного QueueWorker для обработки: lease → run_full → release_done/failed. Остановка — кооперативная отмена.

<a id="9-validation"></a>

### 9. Проверка

Мастер из 3 шагов для реальной проверки CID версии 0.4.1:
- **Генерация** — N вариантов одного исходного. Вызывает GenerateVariantsWorker (оборачивает `tools/generate_variants.py`).
- **Запись** — редактируемая таблица с локальными диагностическими KPI для каждого варианта + пустые ячейки для `upload_date`, `youtube_video_id`, `match_status`.
  `notes`. «Сохранить в validation_log.csv» добавляет запись.
- **Анализ** — запускает `python tools/validation_correlate.py` на CSV и показывает результат (корреляция Спирмена для каждого предиктора).

Ручная загрузка между шагами 1 и 2: см. [docs/validation_harness.md](validation_harness.md) для полного цикла.

<a id="10-settings"></a>

### 10. Настройки

- **Тема** — тёмная / светлая / системная (системная по умолчанию возвращается к тёмной в MVP); применится сразу через сигнал state.theme_changed.
- **Профиль по умолчанию** — предварительно выбран при «Обработка видео» и «Пакетная обработка» при запуске. У Auto-tune есть собственный селектор базового профиля.
- **Обслуживание** — Сбросить кэш кодировщика (удаляет
  `~/.cache/video_uniquifier/encoders.json`), Открыть каталог журналов, Открыть каталог конфигурации.
- **Уведомления** — дополнительная настройка вебхука и SMTP. Метки формы выровнены по центру своих полей; флажки событий и кнопки действий имеют общий фон карточки.
- **Локальная телеметрия** — запись с разрешения на этом устройстве. **Статус** показывает выбранный способ записи и количество сохранённых событий. Изменение галочки вступает в силу после
  **Применить телеметрию**. Папка событий отображается отдельно; наведите курсор, чтобы увидеть полный путь. Запись остаётся локальной и ничего не отправляет по сети.

Сохранение обратной связи появляется рядом с фиксированным действием **Сохранить**, поэтому остаётся видимым при прокрутке страницы.

<a id="where-data-lives"></a>

## Где хранятся данные

Определяется через `QStandardPaths.AppConfigLocation` + `CacheLocation` (v0.7.0 R1 / E3), так что пути соответствуют конвенции каждой ОС. Помощник по миграции копирует предыдущие настройки/историю приложения при первом запуске, сохраняя оригиналы.

|Путь (типичный)|Конвенция ОС|Что|
|---|---|---|
| `<CONFIG_DIR>/state.json`            |macOS `~/Library/Preferences/video-uniquifier`, Linux `~/.config/video-uniquifier`, Windows `%APPDATA%\video-uniquifier`|Тема, недавние, профиль/кодировщик по умолчанию, конфигурация уведомлений|
| `<CONFIG_DIR>/history.json`          |То же, что и выше|История запусков (≤100 записей)|
| `<CONFIG_DIR>/crash.log`             |То же, что и выше|Глобальный журнал трассировки исключений (ротация 100 Киб, v0.7.0 R2 / E6)|
| `<CACHE_DIR>/encoders.json`          |macOS `~/Library/Caches/video-uniquifier`, Linux `~/.cache/video-uniquifier`, Windows `%LOCALAPPDATA%\video-uniquifier\Cache`|Кэш обнаружения кодировщика (сброс через Настройки)|
| `<CACHE_DIR>/work/<plan_hash>/`      |То же, что и выше|Рабочая директория запуска (сегменты, state.json, маркер возобновления)|
| `<CACHE_DIR>/keyframes/`             |То же, что и выше|Кэш сканирования ключевых кадров (срок жизни 30 дней)|
| `<CACHE_DIR>/corpus/index.json`      |То же, что и выше|Индекс отпечатков корпуса|
| `<CACHE_DIR>/batch/<plan_hash>/`     |То же, что и выше|Временные файлы пакетного исполнителя|
| `<CACHE_DIR>/worker/<plan_hash>/`    |То же, что и выше|Временные файлы очередного исполнителя|

<a id="packaging"></a>

## Упаковка

Поставляется стартовый `pyinstaller/video-uniq-gui.spec`. На macOS:

```bash
pip install pyinstaller
pyinstaller pyinstaller/video-uniq-gui.spec --clean --noconfirm
open dist/video-uniq-gui.app    # unsigned: right-click → Open first time
```

На Windows / Linux PyInstaller также может создавать распределение в одном файле. Если PyInstaller не удается на вашей платформе, резервным вариантом всегда является `pipx install 'video-uniquifier[gui]'`, который работает везде.

<a id="troubleshooting"></a>

## Устранение неполадок

**В: PyQt6 не устанавливается на моём Linux.** О: Некоторым дистрибутивам требуется `apt install libxcb-cursor0 libgl1`, прежде чем бинарное колесо PyQt6 будет работать.

**В: QA Viewer показывает ярлык вместо встроенного отчёта.** О: Либо `PyQt6-WebEngine` не установлен (`pip install 'video-uniquifier[gui]'`), либо вы запускаете в headless-режиме (offscreen Qt вынуждает использовать ярлык, потому что встроенный браузер там падает).

**В: Кодировщики выглядят неправильно / недоступны.** О: Настройки → Сбросить кэш кодировщиков. При следующем запуске будет новое обнаружение.
