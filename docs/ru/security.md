# Безопасность

Каноническая политика безопасности поставляется в корне репозитория как [`SECURITY.md`](https://github.com/hostlife22/video-uniquifier/blob/main/SECURITY.md), чтобы GitHub автоматически обнаруживал её и отображал кнопку
**Безопасность → Сообщить об уязвимости**.

<a id="release-inventory-scope-v160-preparation"></a>

## Область инвентаризации релизов (подготовка к v1.6.0)

`tools/bundle_sbom.py` инвентаризирует фактический нативный пакет/извлечённый AppImage, а не пакеты, установленные в несвязанном runner. Четыре документа CycloneDX 1.5 для конкретных платформ включают SHA-256 хэши обычных файлов, цели симлинков и имена/версии пакетов из встроенных Python METADATA. Каждый документ указывает хэш архива и исходный коммит; рабочий процесс релиза проверяет привязки и подписи cosign. Старый `sbom.cdx.json` остаётся явным доказательством среды сборки.

Это использует [представление целостности файлов/компонентов]( https://cyclonedx.org/guides/sbom/relationships/ ) CycloneDX. Покрытие файлов не устанавливает полного графа зависимостей: непрозрачное содержимое PYZ/статических бинарных файлов, внешние библиотеки ОС и полная атрибуция лицензий остаются непроверенными. Cosign аутентифицирует происхождение рабочего процесса, а не нотариальное заверение Apple или Authenticode Windows. Ручная квалификация Docker использует уникальный идентификатор кандидата, а не `latest`/`edge`, когда требуется проверка аттестации реестра.

<a id="reporting-a-vulnerability"></a>

## Сообщение об уязвимости

Используйте один из этих каналов:

1. **Приватная отчетность о уязвимостях GitHub** — на странице репозитория, **Security → Report a vulnerability**, или откройте [прямую ссылку](https://github.com/hostlife22/video-uniquifier/security/advisories/new).
2. **Электронная почта** — `sen.serafim.dev2gmail.com` с префиксом темы
   `[video-uniquifier security]`.

**Пожалуйста, не открывайте публичный issue для предполагаемой уязвимости.**

<a id="supported-versions"></a>

## Поддерживаемые версии

Исправления безопасности применяются в самой последней версии линии MAJOR.MINOR.

|Версия|Исправления безопасности|
|---|---|
|**2.2.x**|✅ активна|
|2.1.x и ранее|❌ срок поддержки истёк|

Полную политику — область применения, сроки раскрытия, зал славы — см. в [`SECURITY.md`](https://github.com/hostlife22/video-uniquifier/blob/main/SECURITY.md).

О приверженности SemVer и порядке предложения критических изменений см. [Версионирование](versioning.md).
