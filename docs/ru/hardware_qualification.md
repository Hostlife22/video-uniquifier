# Проверка оборудования

Обнаружение кодера доказывает, что FFmpeg может открыть устройство для одной конкретной задачи. Это не доказывает, что получаемый поток имеет требуемый профиль, цветовую сигнализацию, частоту кадров или структуру случайного доступа. Бэкенд считается производственно-квалифицированным только после того, как сгенерированный файл проходит реальный контракт битового потока на целевом устройстве и драйвере.

Ручной рабочий процесс `Hardware qualification` GitHub Actions выполняет этот контракт на доверенном собственном исполнителе (self-hosted runner). Он намеренно отсутствует при триггерах push и pull request, поэтому обычная матрица CI ни ждет редкие GPU, ни не выполняет ненадежные изменения на постоянной машине.

<a id="what-is-checked"></a>

## Что проверяется

Рабочий процесс собирает шестисекундный источник 640×360, 24 FPS BT.709 с ограниченным диапазоном через реальный путь `build_plan` и `run_full`. Явно запрошенный кодер должен существовать и завершить выполнение; он не может быть пропущен. Проверки выходного файла включают:

- точный кодек, сигнализация уровня и MP4 sample-entry тег;
- Основной/Высокий профиль и 8-битный пиксельный формат 4:2:0;
- сохраняемое количество кадров, каденс и сигнализация BT.709/диапазона;
- сохраняемый шаблон VFR меток времени 30/20/60 FPS и точное декодированное количество кадров;
- HEVC Main10 HLG/BT.2020/сигнализация ограниченного диапазона, когда энкодер объявляет HEVC;
- отказ по схеме fail-closed для статических HDR10 метаданных на аппаратных путях, которые явно не проверялись на сохранение ST2086/MaxCLL/MaxFALL;
- две одновременные задачи, когда энкодер объявляет как минимум две сессии;
- строгие SDR задания 1080p и 3840×2160 для H.264/HEVC VideoToolbox;
- отмена после того, как аппаратный процесс выдает прогресс, без частичного итогового вывода;
- автоматическое переключение скорости-политики на реальный проверенный программный энкодер, когда соответствующий кандидат VideoToolbox становится недоступным;
- H.264 High/CABAC и закрытая половинная FPS IDR GOP, с одной или двумя последовательными B-кадрами для бэкендов с точным подсчетом или квалифицированным диапазоном VideoToolbox от одного до трех;
- HEVC закрытый IDR и максимальная GOP продолжительностью две секунды;
- интервалы ключевых кадров AV1 не более двух секунд.

`qualification-artifacts` содержит JUnit XML, каждый сгенерированный медиафайл и JSON-отчет с хешами, FFprobe данные кадров/потока, FFmpeg информацию о сборке и доступный инвентарь GPU. Артефакты сохраняются в течение 30 дней. Неудачное утверждение является полезным доказательством квалификации: исправьте и квалифицируйте ту политику поставщика, вместо того чтобы ослаблять контракт или отмечать бэкенд как поддерживаемый только на основе обнаружения энкодера.

<a id="runner-preparation"></a>

## Подготовка раннера

Используйте выделенную машину или временную виртуальную машину с производительным драйвером, запланированной сборкой FFmpeg, `ffprobe`, Git и поддерживаемым Python. Зарегистрируйте её как самоуправляемый агент с меткой ОС по умолчанию плюс одной узкой меткой устройства, например:

|Устройство|Рекомендуемая метка|Типичный выбор кодировщика|
|---|---|---|
|NVIDIA Turing (например, T4)| `gpu-nvenc-turing` | `h264_nvenc,hevc_nvenc` |
|NVIDIA Ada| `gpu-nvenc-ada` | `h264_nvenc,hevc_nvenc,av1_nvenc` |
|Intel Arc / современные встроенные GPU| `gpu-qsv` |поддерживаемый поднабор `h264_qsv,hevc_qsv,av1_qsv`|
| AMD GPU | `gpu-amf` |поддерживаемый поднабор `h264_amf,hevc_amf,av1_amf`|
|Apple Silicon| `gpu-videotoolbox` |поддерживаемый поднабор кодировщиков VideoToolbox|

Не запрашивайте кодек, который физическое поколение не может кодировать. Например, у NVIDIA T4 есть NVENC H.264/HEVC, но нет кодировщика AV1. Рабочий процесс намеренно прерывается, если указанный кодировщик отсутствует или при проверке его реальной способности возникает сбой.

!!! warning
    Никогда не прикрепляйте этот рабочий процесс к `pull_request` и никогда не открывайте длительно работающий
    самостоятельно размещаемый исполнитель для недоверенных форков. Используйте учетную запись исполнителя без прав администратора, изолируйте
    хост/сеть, избегайте секретов репозитория и пересобирайте эфемерные исполнители после выполнения задач
    где это возможно.

<a id="run-and-evaluate"></a>

## Запустите и оцените

В интерфейсе Actions выберите **Аппаратная квалификация**, выберите зафиксированную ветку, метку ОС, метку устройства и точный список кодировщиков через запятую. Эквивалентная команда CLI для запуска:

```bash
gh workflow run hardware-qualification.yml \
  -f runner_os=Linux \
  -f runner_label=gpu-nvenc-turing \
  -f encoders=h264_nvenc,hevc_nvenc \
  -f python_version=3.12
```

Задача может оставаться в очереди бесконечно, если ни один онлайн исполнитель не имеет всех трех меток (`self-hosted`, выбранная ОС и метка устройства). Зеленый результат квалифицирует только записанную ОС, сборку FFmpeg, поколение устройства и драйвер — а не весь вендор. Сохраните артефакт с доказательством версии и повторите выполнение после изменений драйвера, FFmpeg или политики кодировщика.

Локально можно использовать ту же строгую выборку без действий:

```bash
export VIDEO_UNIQ_HARDWARE_ENCODERS=h264_videotoolbox,hevc_videotoolbox

pytest tests/integration/test_encoder_bitstream_matrix.py -vv \
  --basetemp=.qualification/pytest-temp \
  --junitxml=.qualification/junit.xml

python tools/hardware_qualification_report.py \
  --media-root .qualification \
  --output .qualification/report.json
```

Каталог `.qualification` является доказательством, а не управляемым через систему контроля версий элементом. Удалите его после архивирования отчета и медиа, где хранятся ваши записи о выпуске.

На квалифицированном Intel Mac (Intel UHD 630 + Radeon Pro 5300M, FFmpeg 9.0.1) расширенная матрица завершилась с **22 пройдено / 36 пропущено без запроса** для
`h264_videotoolbox,hevc_videotoolbox`. Сохраненный отчет содержит 39 проверенных и хешированных медиа-артефактов, а также доказательства UHD/отмены. Пути кодирования SDR и HLG квалифицированы; статические метаданные HDR10 преднамеренно закрыты на случай ошибки, потому что этот путь VideoToolbox не может подтвердить сохранение ST2086/MaxCLL. Это квалифицирует только эту конкретную комбинацию Mac/FFmpeg; NVENC, QSV, AMF и Apple Silicon остаются отдельными квалификациями исполнителей.
