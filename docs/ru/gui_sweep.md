# Проверка экранов

GUI PyQt6 имеет 10 экранов и 14 фоновых процессов. Набор оффскрин-проверки визуальных регрессий (`tests/visual/test_gui_screenshots.py`,
`QT_QPA_PLATFORM=offscreen`) ловит регрессии формы виджетов, но не может выявлять дефекты композитора / шрифтов / HiDPI / drag-drop / диалогов, которые проявляются только на реальном дисплее. Этот документ охватывает **только для разработчиков** ручную проверку, которая закрывает этот пробел.

Нет CI-хука — эти проверки требуют входа в систему macOS (или Linux с реальной сессией X / Wayland). Запускайте локально перед отметкой релиза, после изменения любого `gui/screens/*` или `gui/workers/*`, а также после обновления PyQt6.

<a id="setup"></a>

## Настройка

```bash
make dev                                                # installs PyQt6
# Real-window run, native platform:
.venv/bin/python -m video_uniquifier.gui.app_pyqt          # interactive
# OR drive the harness (fast, automated, captures PNG + Qt log):
.venv/bin/python tools/gui_sweep.py                     # writes out/gui_sweep/<ts>/
.venv/bin/python tools/gui_sweep.py --smoke-worker      # + tiny RunWorker pass
```

`tools/gui_sweep.py` ОТКАЗЫВАЕТ `QT_QPA_PLATFORM=offscreen` — это покрывается набором визуальной регрессии. На macOS скрипт использует
плагин `cocoa`; на Linux он наследует `QT_QPA_PLATFORM` (`xcb` или
`wayland`). Каркас записывает:

|Файл|Назначение|
|---|---|
| `out/gui_sweep/<ts>/<screen>.png` |PNG 1280×800 по каждому экрану|
| `out/gui_sweep/<ts>/qt.log` |Снятые сообщения Qt (предупреждения, критические ошибки, фатальные)|
| `out/gui_sweep/<ts>/report.md` |Чек-лист триажа с ссылками на изображения|

Читайте `report.md` после каждого запуска — предупреждения Qt о недостающих файлах перевода или несоответствии HiDPI обычно показываются там раньше, чем доходят до пользователя.

<a id="per-screen-checklist"></a>

## Чек-лист по каждому экрану

Для каждого экрана: откройте `MainWindow`, кликните на элемент боковой панели, затем выполните "Проверку" элементов. **Сбой** = любое действие, которое вызывает краш, зависание, тихий отказ в работе, утечку рабочих потоков или отображение явно неправильного содержимого.

<a id="1-run"></a>

### 1. Запуск

- **Взаимодействия**: перетащите файл в поле ввода; выберите профиль; нажмите "Проверка"; нажмите "Предварительная проверка"; нажмите "Запуск" с настройками кодировщика по умолчанию.
- **Проверка**: индикатор прогресса продвигается; строка состояния обновляется по сегментам; кнопка отмены работает во время выполнения; отчет QA открывается по завершении.
- **Следите за**: оставшимися процессами ffmpeg после отмены (`pgrep -fl ffmpeg` после клика).

<a id="2-batch"></a>

### 2. Пакетная обработка

- **Взаимодействия**: загрузите каталог с тестовыми файлами; выберите профиль; установите workers=2; нажмите "Запустить пакет".
- **Проверка**: строки для каждого файла обновляются независимо; пауза работает; возобновление продолжается с последнего завершенного файла.
- **Следите за**: рассинхронизацией состояния строки с рабочим (например, строка показывает "выполнено", но рабочий все еще работает).

<a id="3-calibrate"></a>

### 3. Калибровка

- **Взаимодействия**: выберите эталонный клип; выберите стартовый профиль; нажмите "Калибровать"; следите за журналом итераций.
- **Проверка**: каждая итерация создает дельту отпечатка; предложенный профиль дифференцируется; "Применить" записывает новый YAML.
- **Следите за**: петля калибровки не сходится в пределах лимита итераций (в настоящее время 6) — известно как допустимое, но зафиксируйте заметку о производительности.

<a id="4-qa-viewer"></a>

### 4. Просмотрщик QA

- **Взаимодействия**: откройте существующий `.qa.json` из `out/runs/`; переключайтесь между вкладками видео / аудио / отпечатка.
- **Проверка**: графики отображаются (backend matplotlib); сортировка таблицы работает; загружается полоска миниатюр по сегментам.
- **Следите за**: `audio_fp_similarity == 0.0` ожидаемо (см.
  `docs/en/qa_report.md` Найдено #4) — не отмечайте как ошибку.

<a id="5-profile-editor"></a>

### 5. Редактор профиля

- **Взаимодействия**: открыть `cid_aware.yaml`; переключить трансформацию; изменить числовой параметр; сохранить как новый файл.
- **Проверить**: валидация pydantic срабатывает на некорректный ввод; различия с оригиналом показываются перед сохранением; новый файл читается `video-uniq run`.
- **Следить за**: тихим перезаписыванием оригинала — всегда должна появляться диалоговое окно "Сохранить как".

<a id="6-history"></a>

### 6. История

- **Взаимодействия**: прокручивать журнал выполнения; двойной клик на строке, чтобы открыть её QA-отчет.
- **Проверить**: строки показываются сначала последние; "Открыть результат" показывает созданный mp4 в Finder/Files.
- **Следить за**: накоплением строк без ограничения — известно: автоочистка отсутствует в версии 0.5; создать отдельную заявку, если список превышает 10 000 строк.

<a id="7-corpus"></a>

### 7. Корпус

- **Взаимодействия**: сгенерировать синтетический корпус (вызывается `_corpus_gen.py`); убедиться, что `tests/fixtures/.gen/` заполнен.
- **Проверить**: прогресс по фикстуре; отмена работает; повторный запуск идемпотентен (пропускает существующие файлы, если только не `--force`).
- **Следить за**: гонкой между процессами при одновременном запуске генерации корпуса в нескольких GUI — известно, допустимо, блокировка файлов работает по мере возможностей.

<a id="8-queue"></a>

### 8. Очередь

- **Взаимодействия**: поставить в очередь 3 задачи; приостановить очередь; изменить порядок строк; возобновить.
- **Проверить**: состояние очереди сохраняется после перезапуска приложения;
  Файлы `state.json` для каждой задачи валидны.
- **Следить за**: исполнитель очереди не подбирает задачи после перезапуска (известный частный случай, если `state.json` был в процессе записи во время сбоя).

<a id="9-validation"></a>

### 9. Проверка

- **Взаимодействия**: выбрать журнал "реального CID" (CSV или jsonl); нажать "Коррелировать"; просмотреть таблицу по сегментам.
- **Проверить**: корреляция выполняется до конца; результаты выделяют строки выше порога CID; экспорт в CSV работает.
- **Следите за**: утечкой виджета matplotlib при повторных запусках (известно для некоторых версий macOS; в качестве решения принудительно перезагружайте экран).

<a id="10-settings"></a>

### 10. Настройки

- **Взаимодействия**: смена темы; переключение "показать предзапуск как модальное окно"; указание собственного пути ffmpeg; нажатие Сохранить.
- **Проверка**: изменения сохраняются через `AppState` до `~/.video_uniquifier/`; неверный путь ffmpeg показывает ошибку прямо в интерфейсе.
- **Следите за**: переключение темы, требующее перезапуска — в настоящее время это действительно требуется; указано в подсказке.
