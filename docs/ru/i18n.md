# Локализация приложения

Десктопный графический интерфейс поставляется с английским как исходным языком и русским (`ru_RU`) в качестве первой переведённой локали. Переключение языка простое — Настройки → **Внешний вид → Язык** переустанавливает переводчик и сохраняет выбор на `state.json`. Навигация, заголовки страниц и основной рабочий процесс обновляются немедленно. Некоторые второстепенные экраны/сообщения всё ещё требуют перезапуска, чтобы обновились все строки.

<a id="available-locales-v09"></a>

## Доступные локали (v0.9)

|Локаль|Статус|Покрытие (строки CTA)|Поддерживающий|
|---------|------------|------------------------|------------------|
| `en_US` |источник|н/д|video-uniquifier ядро|
| `ru_RU` |переведено| ≥ 50 %                 |video-uniquifier ядро|
| `zh_CN` |переведено|100 % каталогизированных строк|video-uniquifier ядро|
| `es` |частично|Основные действия|video-uniquifier ядро|
| `pt_BR` |частично|Основные действия|video-uniquifier ядро|

Каталог на упрощённом китайском языке поддерживается в `gui/i18n/zh_cn.py` и объединяется с общим источником. Он охватывает навигацию, введение на страницах, настройки, обработку, воспроизведение/сравнение и все десять контекстных руководств. Имена файлов профилей, идентификаторы кодировщиков, пути, журналы и контент, введённый пользователем, сохраняют свои исходные значения.

Показатель охвата — это доля `SOURCE_KEYS` в
`gui/i18n/translations.py`, которые имеют непустую запись в таблице локали. Она проверяется во время CI с помощью
`tests/unit/test_i18n.py::test_coverage_ratio_ru_is_substantial`, который завершается с ошибкой, если `ru_RU` падает ниже 50 %. Строки без записи по умолчанию используют исходное значение — так задумано.

<a id="why-no-ts-qm"></a>

## Почему нет `.ts` / `.qm`?

Канонический конвейер Qt: `pylupdate6` → `.ts` → `lrelease` → `.qm`. Версия v0.9 намеренно пропускает его:

* каталог поддерживается в приложении — словарь Python легко редактировать и просматривать;
* разработчикам не нужно устанавливать инструменты разработчика Qt;
* wheel поставляется точно с теми байтами, которые написал мейнтейнер, без шага компиляции во время сборки, который может изменяться в разных выпусках.

Переводчик `gui/i18n.RuntimeTranslator` наследует `QTranslator`, переопределяет `translate()` и читает переводы из `TRANSLATIONS[locale]`. Вызовы `QObject.tr()` и `QCoreApplication.translate()` проходят через него без изменений в местах вызова.

Если в будущем локаль превысит несколько сотен строк, компромисс изменится: переходите на `.ts` + `.qm`, сохраняйте тот же публичный API (`install_translator`, `available_locales`), а словарь исчезает как деталь реализации.

<a id="adding-a-new-locale"></a>

## Добавление новой локали

1. Откройте `src/video_uniquifier/gui/i18n/translations.py`.
2. Скопируйте блок `ru_RU`, переименуйте ключ в код вашей локали (используйте форму POSIX, например `de_DE`, `fr_FR`).
3. Замените каждое значение справа на ваш перевод. Пропустите ключ, чтобы использовать английский по умолчанию. **Не** придумывайте новые ключи — тестовая система отклоняет записи, которые не соответствуют строке в
   `SOURCE_KEYS`.
4. Сохраняйте мнемонические маркеры (`&Run` → `&Запустить`). Выберите букву, близкую к английской; Qt выделяет любой символ, который следует за `&`.
5. Запустите `pytest tests/unit/test_i18n.py -v`. Тест покрытия выводит процент вашей локали в строке журнала.

<a id="adding-a-new-translatable-string-in-the-gui"></a>

## Добавление новой переводимой строки в графический интерфейс

1. Оберните её в `self.tr("…")` (или `QObject.tr("…")` для использования на уровне модуля).
2. Добавьте точную исходную строку в `SOURCE_KEYS` в
   `gui/i18n/translations.py`. Сохраняйте список в алфавитном порядке внутри его комментируемого раздела.
3. Опционально добавьте запись `ru_RU`. Пропущенные записи будут использовать значение по умолчанию.

<a id="caveats"></a>

## Ограничения

* Подписи страниц обновляются на `LanguageChange` и когда страница отображается. Общие
  `gui/i18n/widgets.py` помощник запоминает исходные строки для меток, кнопок, заголовков форм, placeholders, подписей комбинированных списков и заголовков таблиц, поддерживаемых каталогом. Он не переводит содержимое редактора или данные таблиц, и блокирует сигналы виджетов во время обновления подписей комбинированных списков, чтобы настройки обработки оставались неизменными. Динамические сообщения должны использовать `tr()` перед форматированием; технические детали ошибок и журналы могут оставаться на исходном языке.
* **Числа и единицы** в настоящее время не форматируются через
  `QLocale` — `1,234` остаются разделенными запятой независимо от локали. Версия 1.0 пересмотрит это, когда появится больше европейских локалей.
* **CLI только на английском.** Перевод вывода, ориентированного на разработчиков (текст помощи Typer, строки журналов), был явно отложен — аудитория состоит из разработчиков, говорящих на английском по всему миру, и изменение этого сломало бы возможность сканирования скриптов через grep.
