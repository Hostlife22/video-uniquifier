# Сравнение с практиками сообщества и рекомендации для video-uniquifier

Дата: **2026-10-04**. База аудита: commit
`03c707a5c4a68397511cb38f881335a00990f271`, версия проекта **2.0.0**.
Это рекомендации по результатам исследования, **не список уже внесённых изменений**.
Код приложения в рамках исследования не менялся.

Практические шаги, зависимости и текущие статусы вынесены в
[рабочий план реализации](../../implementation-plan.md).

Основания: [Hindi/India-focused источники](01-hindi-social.md),
[международные обсуждения](02-international-social.md),
[проверка Content ID и исследований](03-content-id-evidence.md),

## 1. Главный ответ для проекта

По набору автоматических преобразований наш проект уже перекрывает значительную
часть обсуждаемых косметических операций. Его полезное отличие — воспроизводимые
профили, seed, сегментная обработка, resume, preflight и локальная QA-отчётность.
Социальный workflow шире: авторы также выбирают сцены, пишут narration, заменяют
звуковой материал, добавляют комментарий и перестраивают историю.

При этом **ни исследованная социальная выборка, ни наш QA не доказывают надёжный
обход нынешнего Content ID**. Практический разрыв — качество измерения и честная
оценка результата, а также монтажная составляющая. Докупить ещё один фильтр только
потому, что его называют «секретом», недостаточно.

## 2. Сопоставление задач, а не названий приложений

| Практика в найденных источниках | Наше текущее покрытие | Реальный пробел / следующий шаг |
|---|---|---|
| Mirror, crop, rotation, цвет, noise | Соответствующие зарегистрированные transforms | Не считать изменение pHash доказательством внешнего результата |
| Pitch, EQ, noise, compand, reverb, stereo effects | FFmpeg audio transforms в профилях | Проверять A/V sync, разборчивость, пики и mono playback |
| Ускорение / изменение timeline | Есть отдельные temporal/audio операции и compatibility checks | Нельзя переносить параметры редактора в YAML без проверки семантики и длительности |
| Короткая нарезка сцен | Segmenter и scene detection | Техническое разбиение для encoding не равно смысловому монтажу |
| Narration / собственный комментарий | Внешний редакционный этап; subtitle injection решает другую задачу | Потребуется отдельный workflow, если это станет целью продукта |
| Picture-in-picture, сложные маски, B-roll, meme inserts | Не заявлять универсальный compositor по наличию crop/noise/subtitles | Сначала определить формат edit decision list и reference policy |
| CapCut / KineMaster / Alight Motion / VN | Наш продукт автоматизирует пакетную обработку через FFmpeg | Редакторы решают интерактивную композицию; бессмысленно сравнивать только число эффектов |
| CapCut captions / перевод / ElevenLabs в опубликованном workflow | Whisper используется для субтитров; сценарий и voiceover — другое | Не путать ASR с авторским анализом и созданием озвучки |
| Несколько вариантов одного исходника | Seed, профили и calibration | Проверить, какие параметры реально варьируются и сохраняются |
| Проверка готового результата | Correctness / quality / similarity QA | Измерители должны явно сообщать missing/error/unsupported |
| «Пройдёт Content ID» | Такого квалифицированного предсказания нет | Не показывать локальное similarity как вероятность платформенного решения |
| Канал с историей публикаций | Corpus хранит локальные сравниваемые материалы | Локальная база не равна каталогу rights-holder references |
| Монетизация movie recap | Продукт не оценивает YPP и содержательную оригинальность | Это отдельная редакционная и платформенная задача |

Наличие эффекта не означает, что он включён в каждый профиль, совместим со всеми
источниками или участвует в calibration. Точная матрица реализаций, профилей и
ограничений приведена в отчёте 04.

## 3. Приоритеты: что исправлять прежде всего

Ниже **предлагаемая** очередность. P1/P2 — наша оценка важности для интерпретации
результатов, не установленная severity GitHub issue.

| ID | Приоритет | Предлагаемая работа | Почему это следует из исследования | Критерий готовности |
|---|---|---|---|---|
| R-01 | P1 | Исправить fractional scaling integer-параметров calibration | Аудит воспроизвёл невалидный `radius` при дробном factor | Все реально выдаваемые factors создают профиль, проходящий схемы transform и `build_plan` |
| R-02 | P1 | Синхронизировать intensity mapping с реальными схемами | Несколько legacy keys не соответствуют `blackout_prob`, `ratio`, `intensity`, `noise_db`, `luma_amount` | Таблица searchable/scaled/fixed параметров; содержательные тесты настоящих профилей |
| R-03 | P1 | Отдельно показывать available / missing / failed / unsupported metrics | Низкая цифра при отсутствии fingerprint может выглядеть как успешное изменение | Отсутствующая метрика не участвует как валидный ноль; отдельный статус в JSON/HTML/UI |
| R-04 | P1 | Уточнить терминологию QA и обновить устаревшие описания | `match_probability_self` — compatibility name локальной эвристики | В пользовательском отчёте видны единицы, алгоритм, sampling, ограничения, статус; обратная совместимость спланирована |
| R-05 | P1 | Квалифицировать measured similarity на независимой выборке | Самооптимизация под один proxy легко переоценивает результат | Есть holdout, positive/negative pairs, precision/recall и версии моделей |
| R-06 | P1 | Добавить проверки реальной семантики sampled windows и alignment | Изменение скорости/нарезка может нарушить сравнение по одинаковым индексам | Известны timestamps выборки, coverage, offset/speed assumptions; тесты на длинных и retimed источниках |
| R-07 | P1 | Проверять деградацию temporal/audio отдельно от similarity | Blackout/drop и шум могут уменьшить metric, ухудшив продукт | Корректность timeline, отчёт эффектов, экспертная A/B-оценка и воспроизводимые samples |
| R-08 | P2 | Пересмотреть описание профилей `cid_*` | Название может подразумевать внешнюю квалификацию, которой нет | Описание обозначает experimental/local scope; переименование только через совместимость/RFC |
| R-09 | P2 | Исследовать scene-aware sampling и segment localization | Открытые VCD работы показывают зависимость от отбора кадров | Сравнение fixed/scene-aware на том же holdout, с измерением затрат |
| R-10 | P2 | При необходимости спроектировать монтажный workflow | Narration/B-roll/сценарий не сводятся к FFmpeg jitter | Определены пользовательская задача, EDL, audio tracks, subtitles, reference registration |

**R-01 и R-02 — конкретные обнаруженные проблемы реализации.** R-03 и R-06
включают design gaps и случаи, для которых требуется отдельная квалификация.
R-09 и R-10 — предложения исследования/развития, а не обнаруженные баги.
Не следует превращать всю таблицу в десять «подтверждённых неисправностей».

Аудит также обнаружил, что некоторые тесты intensity используют legacy-поля ради
покрытия ветвей. Зелёный такой тест не доказывает валидность настоящего YAML-профиля.
Добавлять нужно проверки пользовательского результата: loaded shipped profile →
scaled candidate → transform schema → plan → при необходимости короткий ffmpeg
render. Это устраняет именно воспроизводимый сценарий, а не дублирует формулу.

Изменение стабильных профилей, CLI, API и contract fields должно пройти процесс
RFC и совместимости, описанный в
[CONTRIBUTING.md](https://github.com/Hostlife22/video-uniquifier/blob/03c707a5c4a68397511cb38f881335a00990f271/CONTRIBUTING.md)
и [API contracts](../../api-contracts.md). В этом исследовании такой change не
вносится и переименование `cid_*` не выполняется.

## 4. Как проверять «фишку», чтобы результат был интерпретируемым

Для каждой гипотезы хранить отдельные вопросы:

1. **Операция:** получилось ли применить заявленное преобразование к файлу?
2. **Корректность:** читается ли файл, сохранены ли timeline, sync и требуемые streams?
3. **Качество:** приемлем ли результат для зрителя относительно подходящего reference?
4. **Локальное распознавание:** что показывают независимые измерители и где совпадения?
5. **Платформенное наблюдение:** что фактически показал YouTube для разрешённого материала?
6. **Права/монетизация:** какое основание публикации и какой отдельный статус YPP?

Разделение не усложняет рецепт ради формальности. Оно позволяет понять,
почему результат отличается: отсутствующая метрика, изменённая reference-версия,
неудачное декодирование, плохой звук или реальный эффект на конкретном matcher.

Минимальная карточка эксперимента:

```yaml
experiment_id: example-owned-media-001
research_hypothesis: crop changes this local matcher score
source_id: owned-clip-001
source_sha256: recorded-before-render
rights_basis: owned-or-licensed
code_commit: 03c707a5c4a68397511cb38f881335a00990f271
profile_id: recorded-profile-id
effective_profile: path-to-validated-profile
run_seed: recorded-in-run-manifest
ffmpeg_build: recorded-version-and-filter-support
metrics:
  correctness: separate-result
  quality: separate-result-with-reference-policy
  phash: value-and-sampling-or-status
  audio_fingerprint: value-and-version-or-status
  sscd: value-model-hash-and-sampling-or-status
platform_observation:
  performed: false
  baseline_match_verified: false
  upload_timestamp: null
  claimed_segments: null
  final_observation_timestamp: null
```

Это **предлагаемый исследовательский формат**, не существующий contract нашего
продукта. `null` означает отсутствие наблюдения, а не отсутствие claim.

## 5. План локальной квалификации на своих / разрешённых материалах

### Этап A: проверить calibration и полноту метрик

Предлагаемый небольшой pilot: **6 клипов × 3 профиля × 3 seed = 54 результата**.
Покрыть SDR/HDR, 24/30/60 FPS или VFR, речь/музыку/беззвучный источник, статичную
и динамичную сцену. Эти свойства могут совмещаться; шесть клипов не составляют
репрезентативную выборку для всей библиотеки фильмов.

Проверить валидность всех кандидатов до render, список реально меняемых параметров,
наличие fingerprints, correctness, registration support и сохранение manifest.
Для unsupported режима quality результат должен быть обозначен как unsupported.
Отдельно сравнить sample-предсказание calibration с full-file QA на тех же файлах.

**Критерий перехода:** нет невалидных кандидатов и скрытого metric failure;
не обнаружен timeline/stream regression; результаты можно воспроизвести по manifest.
Число успешных локальных renders не является числом успешных обходов Content ID.

### Этап B: holdout и независимые детекторы

Предложение для следующего исследования: **30 клипов**, из которых 20 используются
для выбора параметров и 10 остаются нетронутым holdout до финальной проверки.
Разделять по исходным произведениям/семействам, а не по случайным кадрам одного
фильма. Добавить unrelated negative pairs и похожие, но разные сцены.

Измерять отдельно:

- Precision/recall поиска преобразованной копии на размеченной локальной базе.
- Segment localization: где именно найден скопированный фрагмент.
- pHash и SSCD как разные predictors, не как подтверждения друг друга.
- Audio matching с выравниванием, а не только пересечение целых fingerprint-чисел.
- Качество при подходящей регистрации, плюс субъективный просмотр/прослушивание.
- Время, память, размер descriptor, размер output и доступность зависимостей.

Нельзя подбирать threshold на этих десяти holdout-клипах, затем называть их
независимой проверкой. При новых настройках нужен новый holdout или заранее
описанный nested evaluation.

Для аудио существует открытый
[Pexeso Audio Fingerprinting Benchmark Toolkit](https://github.com/Pexeso/audio-fingerprinting-benchmark-toolkit)
с file/segment-level evaluation и размеченными искажениями. Его можно использовать
как дополнительную методологию. Лицензия toolkit и права на конкретные записи
проверяются отдельно. Датасеты в рамках этого отчёта **не скачивались**, модели
не переобучались и benchmark не запускался.

### Этап C: внешнее наблюдение при участии владельца references

Только локального исследования недостаточно, если вопрос именно о YouTube.
Для интерпретируемой проверки нужен собственный или разрешённый материал и
сотрудничество владельца corresponding reference. Контрольная неизменённая версия
должна подтверждённо совпасть; иначе отсутствие claim после фильтра не доказывает
ничего о фильтре.

Далее фиксировать один фактор за раз, claim type, claimant, временные интервалы,
territory/policy, время наблюдения и все отрицательные исходы. Наблюдения через
24 часа / 7 дней / 30 дней — **предложенные контрольные точки исследования**,
не официальные сроки работы Content ID и не гарантия постоянного результата.

Даже такой тест даст оценку для выбранных материалов, даты и условий. Разрешение
на фильм не означает автоматически наличие или контроль reference в Content ID.
Не включать в знаменатель ролики без подтверждённого baseline match и не смешивать
claim, блокировку, strike и отказ монетизации.

## 6. Как интерпретировать возможные результаты

| Наблюдение | Корректный вывод | Неподтверждённый вывод |
|---|---|---|
| pHash уменьшился, SSCD почти не изменился | Разные визуальные признаки реагируют по-разному | «YouTube точно не найдёт» |
| Jaccard равен 0 при отсутствии `fpcalc` | Audio diagnostic недоступен | «Аудио уникализировано на 100%» |
| SSCD снизился только на кадрах calibration | Возможна подгонка под samples | «Полный фильм готов» |
| VMAF высокий на registered reference | Мало измеренных encode-искажений в поддержанном режиме | «Текст, кадрирование и редакционная оригинальность безупречны» |
| Видео доступно, есть claim monetize | Совпадение найдено, применена соответствующая политика | «Обход успешен, автор получает всю выручку» |
| Modified upload без claim, baseline тоже без claim | Этот эксперимент не проверил влияние операции на обнаружение | «Фильтр работает» |
| Baseline matched, modified без claim на проверенную дату | Есть конкретное наблюдение отсутствия claim для этой версии | «Одинаково работает на всех фильмах» |
| Narration/B-roll добавлены, QA прошёл | Есть новый монтаж и технически приемлемый файл | «YPP автоматически одобрен» |

## 7. Какие результаты включать в продуктовые обещания

Подтверждённые возможности можно описывать прямо: пакетный render по профилю,
воспроизводимость seed, resume, сохранение streams в поддерживаемых режимах,
diagnostics локальной похожести, зарегистрированная оценка encode-quality.
Для каждого backend и transform сочетания сохранять qualification scope.

Заявления «обход Content ID», «уникальность 95%», «безопасные 5 секунд» и «готовность
к монетизации» требуют отдельных доказательств и определённого исхода. Наша
локальная similarity шкала этих исходов не измеряет.

Для пользователя полезнее отчёт с конкретным ответом: какие части похожи,
какие metrics доступны, где ухудшилось качество, какие streams сохранены,
что происходило с timeline и как воспроизвести результат. Это снижает количество
необоснованных решений и помогает готовить версии собственного контента.

## 8. Что сделано и что остаётся предложением

Выполнены публичный поиск, проверка первичных источников, чтение реализации,
сопоставление transforms/profiles/QA/calibration и read-only воспроизведение
обнаруженных calibration проблем. Результаты проверок перечислены в отчёте 04.

Не выполнены изменения кода, загрузки тестовых фильмов на YouTube, измерение
успешности обхода и full-file benchmark всей библиотеки. Соответствующие этапы
выше описаны как будущие эксперименты с конкретными критериями результата.
